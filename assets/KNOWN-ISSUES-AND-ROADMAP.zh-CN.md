# v3.4.0 已知问题与迭代计划

v3.4.0完成DSH rc.3原生协议适配、恢复一致性、模型恢复策略和现有执行工具接入。它没有建设完整多语言执行平台，也不保证长程任务可以无限期无人值守运行。

## 已知问题与实际影响

| 范围 | 现状/可能表现 | 当前处理 |
| --- | --- | --- |
| 供应商额度与限流 | 界面显示余量时，Google仍可能返回429；Codex也可能发生独立传输失败 | 尊重实际请求和恢复提示，按次数/时间预算重试回退；不把连接错误解释为额度耗尽 |
| 跨模型历史 | 某些模型对thinking/thought_signature有历史格式约束 | 新会话级错误不扩大为其他会话的模型隔离；不自动重放或改写旧历史 |
| 旧模型健康状态 | 旧快照没有原错误message时，不能证明隔离仅源于会话格式 | 保留保守隔离，不凭猜测清空；需要原故障事实和只读诊断 |
| 未知等待与清理 | 未知句柄、未停净进程、清理失败或未知副作用会使任务停在恢复门禁 | 保留原身份/输入，明确返回待核对或incomplete；新“继续”不替代核对 |
| Notebook状态 | 变量仅在同一委派内持久；完成视图为64份/总16MiB进程内LRU | 结束停核；服务重启、缓存淘汰或超大Notebook前需获授权保存.ipynb |
| Notebook环境 | 用户原选环境不一定属于已核验运行池 | 允许读草稿/元信息；计算前显式选择，不静默替换或污染项目环境 |
| 隔离与配额 | 受管Notebook有文件/网络隔离、每进程限制和墙钟超时；不是完整cgroup总配额或microVM | 不把当前限制宣传为完整沙箱平台；普通standard Notebook维持原语义 |
| 执行入口 | 写入只支持已核验的Linux本机/API Worker路径 | 需要bwrap/native linux-scope；不放行PTC、持久终端或原生Codex/Claude CLI私有写入 |
| 兼容补丁 | 依赖精确rc.3版本和字节，第三方兼容版本由本发布维护 | 未知版本/摘要拒绝；未来rc或上游升级需要重新验证 |
| 界面 | Subscriptions浮层使用CSS anchors | 已在现代浏览器验证，旧浏览器未作覆盖保证 |
| 可选服务 | MCP进程关闭、外部登录失效或业务依赖缺失会显示离线 | 不将“插件active”视为外部服务可用；用户自行管理凭据与服务 |

旧会话/团队的持久控制身份存在歧义时仍须遵守恢复门禁。同一delegation更换child后的旧控制记录不自动回收，不从死亡PID、空jobs或turn/end推断可恢复写权限。

## 迭代顺序与验收标准

以下为后续计划，尚未发布；时间和版本划分随用户反馈调整。

| 优先级/候选版本 | 计划 | 完成标准 |
| --- | --- | --- |
| P0 / 3.4.1 | 根据用户实测修复续接、Notebook与第三方回归；自动化兼容包与版本矩阵核验 | 每个真实问题有旧版失败、新版通过及精确包Host回归；未知身份仍拒绝；下载资产可复现 |
| P1 / 3.4.2 | Notebook数据快照、显式保存/恢复和清晰的只读UI | 跨服务重启恢复cell/输出；权限和项目隔离不变；不把数据恢复当成活内核或变量恢复 |
| P1 / 3.4.x | 供应商拒绝原因、等待窗口和恢复过程的可解释展示 | 脱敏trace能关联一次请求、失败类型、预算与恢复时刻；不泄露账号/凭据；取消与并发测试通过 |
| P2 / 3.5.0 | 在测量后引入Python/JS/TS kernel registry、项目依赖快照、统一执行结果与差分 | 真实任务证明收益；项目/agent依赖不串用；冷启动、内存、取消和重启有基准；保持现有门禁 |
| P2 / 3.5.x | 执行观测与评测集、持久浏览器profile的授权生命周期、每组资源配额 | 逐工具耗时/退出码/输出可追溯；所有自建服务与浏览器可确认停净；真实边界验证失败即拒绝 |
| 研究 / 3.6+ | 容器/gVisor/microVM、凭据代理、网络白名单、快照与回滚 | 先确定威胁模型和资源预算，再做隔离/凭据泄露/逃逸负向测试；不以静态对接宣称生产完成 |

P6继续采用测量驱动的小范围优化。v3.4.0的热缓存合成恢复测量只证明指定样本的改善，不能外推为冷盘、真实长会话或所有机器的时延保证。不把LayerFS或存储重写作为这些阶段的前置条件。

## 报告问题时需要的信息

提供DSH/Swarm/第三方版本、可重复步骤、脱敏错误code和发生时间即可。避免公开token、OAuth文件、完整会话、私人工作树或原始工具输出。涉及未知写入和清理失败时先保留证据，勿删除锁、手改状态或重复执行原操作。
