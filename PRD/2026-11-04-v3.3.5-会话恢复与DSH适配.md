# 百工 v3.3.5 会话恢复与 DSH 0.2.2-rc.1 适配

## 背景与目标

修复指定历史会话中持久子会话的控制、委派与线程身份恢复失败；在隔离环境核查并适配 DSH 0.2.2-rc.1，再安全更新在役 DSH 与百工插件。保留原始任务、子会话、未确认操作及已有用户配置。

## 范围和拟改文件

先对目标会话的事件日志及状态作只读、脱敏的复制和核对。依据实际不一致成因，最小修改百工会话恢复、相关状态或路由适配模块；增加覆盖真实数据形态及反例的回归测试。再针对新宿主变更审计 agent.model、请求路由、工具准入、Session/Projection、Cordis、动态请求头和客户端集成等实际使用的接口，必要时修改对应适配层、兼容性文档和版本元数据。计划在隔离 worktree 开发，不覆盖现有工作树。

## 依赖、数据结构与 API

目标宿主依赖以官方 npm 的 0.2.2-rc.1 为准；本机 Node 24.22.2 满足最低 Node 24.9。确需变更时记录 package.json 和 lock 文件。不预设数据库迁移；若状态持久化模式或 API 契约发生变化，须先设计兼容验证与回滚，禁止直接覆盖账本或重放未知副作用。

## 风险

恢复时身份必须可由现有证据证明；未知写入、未终结任务和真实外部调用不得仅凭确认或新建子会话重放。DSH 升级涉及全局安装、profile 依赖和单实例服务，升级前检查活动会话、备份配置与可回滚的包；兼容未通过不替换在役服务。现有 Inspector 临时禁用和 OpenCode Go 路由须保留，除非验证支持安全调整。

## 验证方式

真实目标会话只读诊断；同形数据的正反回归、完整构建和适用测试；独立宿主启动与关键功能回归；在役切换后核验版本、服务、认证页面、模型目录、目标会话只读恢复、Jev 与路由。明确尚未覆盖的真实写入、交易与长时运行边界。

## 回滚

保留变更前完整 profile 配置、依赖包与目标日志的只读快照；回滚使用事前捕获的准确文件和包，不以 git HEAD 覆盖用户变更。任何持久状态修复须留存时间戳、摘要及可验证的逆操作，并避免覆盖后续并发写入。

## 0.2.2 模型切换兼容实验

官方 0.2.2-rc.1 在工具与提示词装配前冻结模型，同一步普通重试不允许更换模型。为保留用户要求的自动回退，隔离实验拟对该版本 `@deepseek-ai/dsh-agent-loop` 添加版本受限桥接：步骤准备前请求百工选择模型；明确的模型请求失败且原工具尚未执行时，在同一逻辑步骤重试前重新解析模型、工具及提示词。非百工会话沿用官方行为；不会通过修改用户 `model/selection` 事件伪装人工选模。该补丁改变官方同一步固定模型的默认语义，只有通过真实宿主故障注入、已执行工具不重放、取消与权限隔离等验证后才可考虑上线。

## 两个开源项目的参考与隔离实测

- `dsh-model-pool`：GitHub 主分支提交 `a3415e739a2550160921bd824799306d7cbe3b60`，其清单为 0.2.7；本机查询到 npm latest 为 0.1.1。它提供虚拟 ModelPool、独立池、同源重试与冷却，最终仍在 `agent/request` 应用模型覆盖。
- `dsh-llm-fallbacks`：GitHub 主分支提交 `ed4f91aed84430881203472a8650238193d6cb64`，npm 0.6.13；以 `agent/request-error` 做失败决策并在 `agent/request` 应用切换。
- 使用未打桥接补丁的官方 0.2.2-rc.1、隔离 profile 和本地确定性 mock 注入 QUOTA：model-pool 的真实模型链请求顺序为 bad、bad、bad、bad，随后宿主拒绝切换 good；其 ModelPool/Auto 路径在第一次失败后也因请求路由与已冻结虚拟模型不同而拒绝。fallbacks 0.6.13 请求 bad 后尝试 good，同样被宿主拒绝。测试未调用真实提供商。
- 可参考错误类别、冷却、请求范围与账户范围隔离，百工已有相应健康状态与复原机制；不直接叠加两个全局路由器，也不无条件复制固定三次同源重试，因为明确 pool exhausted、认证隔离或供应商 resetAt 需要不同处理。真实模型、配额和长期恢复仍须单独验证。

## 新版隔离验证进展

- `0.2.2-rc.1` 模型桥接：18 项真实 AgentLoop 回退场景、16 项连续子会话/权限/状态/升级场景和 19 项流程/语言/额度/数学场景通过；另有版本绑定的补丁应用、重复应用、回滚及未知摘要拒绝测试。测试供应商为本机 mock，不证明真实账号额度。
- 条件工具测试：失败模型不拥有备用模型专用工具，切换后重新解析并恰执行一次；两次 request/header 记录各自真实模型，未生成伪造的人工选模事件，用户消息保留一次。
- 当前 profile 的 `rc.5` 专用组合包先在独立副本中适配：注册 59 个量化工具与 17 个浏览器工具；离线 SMA、空输入、非法输入、风险、因子、下一根 bar 模拟成交、计算器、财务比率通过；浏览器仅访问本机测试页面并保存测试截图；`@` 文件引用在隔离 Web 页面检索并插入成功。
- 订阅插件、Qwen 包装器和 OpenCode Go 候选在无真实凭据的环境注册；Qwen、OpenCode Go 和 OpenCode Zen 只对本机或进程内 mock 端点发出请求并收到预期回复。OpenCode Go 的生成请求携带会话头；额外的自动标题请求与主对话请求分别观察。空 OpenCode 动态配置的注册/增删测试通过。
- 原生 Codex、Claude 后端、RigorQuant preset、Agent Teams 服务及隔离 lane 注册可见，未进行真实订阅登录或模型生成。RigorQuant 路由的桥接经其自身 mock 路由测试验证，尚不能作为真实研究工作流验收。
- 当前 profile 的去凭据副本使用新版宿主与候选依赖完成组合装配；为避免触碰真实服务和数据，禁用 14 个外部连接组件，Web 页面与百工 14 条路由入口可加载；该结果不代表被禁用组件已验证。
- 将目标历史会话、8 个子会话、事件日志和 ledger 的 11 个文件复制到隔离目录，使用新版宿主真实冷读取目标子会话成功；随后对原始 11 个文件重新计算 SHA-256，均未变化。没有发送原任务、模型请求或订单。
