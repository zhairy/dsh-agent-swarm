# v3.1.6 代码审计、发布精简与稳定性修复

## 1. 背景

v3.1.5 已通过现有单元和集成测试，但发布包仍可能包含内部计划、证据、测试或日志等非运行时内容；若干长期运行路径缺少资源回收和版本单一来源约束。需要在保留 v1 状态兼容和现有业务语义的前提下完成小范围修复。

## 2. 目标

- 审查运行时、数据管道、模型路由、客户端订阅和发布链路。
- 删除已证明无用的源码符号，收窄发布包内容。
- 让 Mermaid 解析器版本从唯一依赖来源读取。
- 确保取消后的任务视图、跨连接遗留请求和一次性专家控制均保持硬上限。
- 修复任务终结跨根同名 `T-1` 误删与最后一条记录未持久化的问题。
- 修复模型面板关闭后永久忙、Mermaid 初始化抛错后续加载永挂、模型目录读取无限 loading。
- 发布版本化 tarball 与稳定下载别名，并保证用户文档只引用包内真实路径。
- 完成类型检查、单元、集成、真实 DSH 宿主和 Web UI 验证后再发布 v3.1.6。

## 3. 修改范围

- `src/workflow.ts`、`src/service.ts`：统一 Mermaid 版本来源。
- `src/agent-control.ts`、`client/task-view-store.js`：有界回收一次性控制记录与任务视图缓存。
- `tests/unit/*`：版本来源、缓存回收和客户端回归。
- `package.json`、`scripts/pack-release.mjs`：发布白名单、依赖安全更新和打包禁止项。
- `README.md`、`docs/*.md`、发行说明：用户可见说明。

## 4. 非目标

- 不改变任务、门禁、验收、租约、Jev 判断或模型路由的业务含义。
- 不删除仍被公开导出、旧版恢复、构建脚本或动态加载使用的模块。
- 不为微观常数收益重写状态分片、DAG 或客户端状态存储。

## 5. 风险与控制

- 依赖升级必须保持 Mermaid 生成、投影和 SVG 安全检查的现有测试通过。
- 发布白名单变化必须用 `npm pack --dry-run --json` 验证运行时闭包完整且内部材料缺失。
- 缓存回收只处理已经没有活动订阅且传输已经结算的条目，不能改变不合作传输的硬上限。
- 控制记录清理必须同时绑定根会话和任务 ID；删除后即使记录集为空也要写入所属根会话。
- 发布资产与文档链接必须在隔离安装后验证，不能只验证源码工作区。
- 回滚可恢复 v3.1.5 的源码与 profile 备份，不回滚已提交业务状态。

## 6. 验证

- `npm run typecheck`
- `npm test`
- `npm run test:integration`
- `npm run build`
- `node scripts/pack-release.mjs --check-only`
- 隔离安装与运行时导出加载
- 真实 DSH `0.2.1-rc.3` 宿主、唯一 3080 监听和 `agent-browser` 关键交互
- 正反独立审查、Jev 七类辅助判断与发布资产校验

## 7. 回滚

恢复 v3.1.5 tarball 或 profile 备份后重启 `dsh-web.service`。源码回滚不得覆盖当前工作树中与本任务无关的用户修改。
