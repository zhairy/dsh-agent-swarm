# 保留工作树的显式授权恢复

## 背景与目标

v3.3.5 保留旧工作树绑定，但没有在合法新 attempt 下转移所有权的通道，导致旧现场不能接管、新建又被守卫拒绝。本修复保留 create_worktree 的新建语义，新增仅接受 worktree_id 的恢复工具；真实路径、仓库、分支和旧 owner 均来自服务端记录。

## 修改范围

- worktree-binding.ts：增加当前 attempt 身份、受控转移、撤销旧索引及按顺序恢复最新 owner；重启始终为 recovery-required。
- application/worktree-recovery.ts：串行恢复事务、旧执行停止确认、排他租约、取消与版本复核、先持久提交后发布。
- adapters/dsh-host/worktree.ts：通过 Host 的文件、受限 subprocess 与 workingDirectory 服务核验原现场和切换 CWD。
- application/swarm-service.ts、service-api.ts、index.ts：接入任务身份、生命周期、在途写入计数、持久日志及租约释放。
- application/host-guards.ts、host-contract.ts、approval-policy.ts、role-registry.ts、task-tools.ts：工具注册、写入角色与审批边界、实际 CWD 和有效租约检查。
- event-journal.ts：新增受支持的 worktree/restored 事实；不使用吞写入错误的 legacy AddLedgerEvent 作为提交屏障。
- tests/*.test.mjs：使用已在 npm test 内执行的 node:test，覆盖无损接管、拒绝路径、故障与重放。

## 数据与 API

新增 swarm_restore_worktree({worktree_id})；不允许模型指定 owner/path。现有创建事实兼容读取；新创建和恢复记录带当前任务版本、node、attempt、delegation 及核验指纹，写入现有 EventJournal。无私有 sidecar、数据库结构迁移或新增依赖。

## 安全与并发

先确认当前 Worker 的授权与任务版本；拒绝尚未停止的旧执行、在途写入、后台作业、未知副作用和其它写者。任务锁与不排队的排他工作树租约覆盖完整恢复窗口。Host 文件/Git 核验确认 realpath、允许范围、common-dir、注册路径、分支和目录身份；HEAD 可包含基线后的合法提交。切换 CWD 后再次核验授权、取消、现场和有效租约，可靠落盘后才发布 active owner。失败或重启保持禁止写入，原工作区文件不改动。

## 验证

在临时 Git 仓库创建后续提交及 staged/unstaged/untracked 文件，比较恢复前后 HEAD、分支、index、文件字节与状态。测试旧 owner 迟到写入、跨任务/旧版本/撤销身份/目录替换/符号链接越界、活跃写者、并发接管、幂等、CWD/持久化失败、异步等待期间取消与版本变化、提交前后中断和重启。npm run typecheck 与 npm test 的输出必须明确收集新增用例。真实用户工作树仅作只读核验，不启动原工程任务。

## 回滚与交付

保留原 3.3.5 包、在役配置与相关日志快照。新包独立按摘要安装，服务空闲时切换并验证；旧记录兼容读取。回滚不能覆盖后续日志或恢复旧 owner 写权限。既有 D14 缺陷与复核、审查门禁不因工具恢复成功而自动关闭。

## 实施与验证记录

- 恢复工具已通过 task-tools 注册链和可写角色白名单接入。创建绑定也改为在可等待的 tools/execute 阶段完成租约与持久提交，tools/result 通知不再授予权限。
- 普通写入在真正分派前复核当前身份和租约，并通过 Host 再次核验目录身份；等待审批期间捕获的旧 attempt 不能在新 attempt 下继续执行。
- advisory 模式未匹配到可预约 DAG 节点时，仅保留服务器实际准入的执行身份，不再把未经预约的调用方 node_id 写成已获授权节点；enforced 的节点准入规则保持。
- `npm run typecheck` 通过；`npm test` 实际收集并通过 33 项 Node 测试，0 跳过。新增用例覆盖真实临时 Git 仓库无损接管、并发/越权/目录替换、实际 service 委派 A/B、在途写入、幂等、取消、日志失败和重启重放。
- 既有 Vitest 回归：132 个文件，1704 项通过、14 项原有跳过。新增恢复测试不依赖这些跳过项，均已进入 npm test。
- 在真实 DSH 0.2.2-rc.1 隔离宿主中，production Host adapter 完成受限 Git/目录核验及 workingDirectory.set；恢复前后 HEAD、分支、index、staged/unstaged/untracked 文件一致，旧 owner 索引移除，0 次模型调用。
- 发布闭包检查：114 个入口依赖文件、399 个打包文件，缺失与禁入文件均为 0。没有新增依赖。
- 指定历史会话的 legacy 与 V2 工作树记录已用新 registry 只读重放，原路径保留为 recovery-required。没有对用户工程执行恢复或写入。
- 一旦新版本已写入 worktree/restored 或新的工作树授权事实，不能直接换回不识别这些事件的旧插件；回滚必须继续保持恢复守卫并保留新日志。
