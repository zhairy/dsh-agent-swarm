# DSH Agent Swarm 3.3.0 Strangler 完成计划

## 1. 目标与版本

- 原始计划：`PRD/2026-11-02-v3.2.0-event-driven-swarm.md`。
- 基线：已发布的 `v3.2.1`，合并提交 `0df99d7a4b702de4498e211ba322dce0923e8647`。
- 目标版本：`3.3.0`。不重写已发布 tag；本版本完成原 3.2.0 未完成的运行时接管和清债。
- 架构参考：`dsh-superagent-prototype@6337fc823ce20251c8de8085948165c81aaa701e`，MIT。
- 外部兼容：14 个角色、主要工具名、provider/model 链、DSH 权限和证据语义保持；旧内部 state layout 仅允许 Importer 读取。

OpenAI 模型元数据另行修正：官方 `openai/gpt-6.1-sol` 的权威规格为 `contextWindow=1050000`、最大输入 `922000`、最大输出 `128000`。DSH 0.2.1-rc.3 的 pi-ai 1.4.0 与 pi-ai 1.5.0 目录仍错误地声明为 `272000`，本机 profile 使用精确 `contextWindow=1050000` 覆盖，不由 Swarm 猜测或篡改其他 provider。

## 2. 完成定义

只有以下条件全部成立才允许标记完成：

1. `service.ts` 不再直接实现任务、委派、路由、授权、规划和 host 守卫；只保留组合根和应用 API。
2. RouteEngine 是模型资格、资源、健康、候选、准入、回退和恢复的唯一生产执行路径。
3. TicketRepository 与版本化 Ticket 生命周期驱动任务读写；旧 TaskRecord 兼容仅在 Importer/导出层。
4. Durable State Journal 是状态唯一提交来源；业务 EventJournal V2 可从提交事实确定性重建，不再依赖旁路 catch 吞错。
5. EventJournal 支持 64 KiB 行上限、64 MiB 封片、跨片 digest、尾损坏恢复和 10 万事件重放。
6. 3.1.9/3.2.x 状态和旧 ledger 有幂等 Importer、manifest、差分报告与回滚备份。
7. Router/Worker 身份、工具拒绝、submission revision/lease/input digest 在生产入口强制执行。
8. Watchdog 接入服务生命周期，产生告警并在未知副作用/过期租约时暂停新自动派发。
9. `off / observe / auto` 驱动实际 admission；默认 observe，显式用户请求照常处理。
10. Continuable Session、Lease、Slot、outbox、等待输入和 shutdown 有可恢复状态。
11. settings-page 拆为 catalog、draft、route-card、JEV、policy、planning/math、save-flow 模块；模型卡默认全收。
12. 任务页只读 Ticket/Route/Health/Progress projection；不在 UI 重新计算激活和证据门禁。
13. Host Adapter 隔离 DSH 版本差异；领域层不读取 Node fs、React 或 DSH context。
14. 删除 `route-state.ts`、旧 `route-engine` shim、旧 side-mirror bridge、service 内旧实现和失效兼容分支。
15. Golden、差分、迁移、恢复、性能、UI、Host 兼容测试全部通过。
16. 两轮正反审计、Jev 七类审核、真机迁移/回滚演练和浏览器验证完成。

## 3. 阶段与检查点

### 阶段 0：基线

- 锁定 3.2.1 公共工具、RPC、角色、配置、路由事件和错误码。
- 建立 `strangler-golden` 场景与 baseline digest。
- 构建后再跑全量测试，消除“未构建 lib”导致的位置测试假失败。

### 阶段 1：Event Core

- State Journal 与业务 EventJournal 建立明确主从边界。
- EventJournal 改为迁入式写入：写失败不得静默吞掉。
- 确定性事件 ID，支持旧 ledger 幂等导入。
- 封片、跨片校验、projection cache 和性能测试。

### 阶段 2：Route Engine

- 将现有 RouteState 注册表迁移到 `application/routing`，接入领域 eligibility/failure fact。
- 目录、额度、认证、健康、升级、上下文准入和 fallback 收敛为一个 engine API。
- 旧路由文件删除；service/delegate 只依赖 engine 接口。
- Golden 路由和 3.2.1 上下文准入全部回归。

### 阶段 3：Ticket/Assignment

- TicketRepository 管理 TaskRecord 的持久化投影和 Ticket 状态转换。
- AssignmentEnvelope 在生产委派路径校验身份、权限、revision、leaseEpoch 和 inputDigest。
- Programmatic projection 与 Event replay 差分一致。
- 旧 TaskStore 内部读写改为 repository 接口。

### 阶段 4：Host/App 拆分

- 从 `service.ts` 提取 Task/Delegation、Authorization、Planning/Review、Acceptance、Control、Guards、RPC。
- Host Adapter 隔离 ctx services 与版本差异。
- service 变组合根，业务模块只依赖 ports。

### 阶段 5：Watchdog/Recovery

- 单服务 watchdog timer、assignment heartbeat、lease 和 queue 检查。
- Outbox dispatcher 支持重启恢复；未知外部副作用只 quarantine。
- shutdown 有界回收，输入和提交意图持久化。
- 迁移、恢复、回滚演练。

### 阶段 6：UI 重写

- settings 控制器和 React 组件按模块拆分。
- route card/catatalog/form/save flow 独立测试。
- 任务视图只消费 projection。
- 模型卡默认收起和错误展开行为保持。

### 阶段 7：切换与清债

- 生产入口全部指向新模块。
- 删除旧路径、legacy sidecar/mirror 和无调用代码。
- 静态架构守卫禁止 domain 向 application/adapters 反向依赖。
- 全量回归、性能、审计、Jev、真机部署、浏览器验证。

## 4. 数据与回滚

- 迁移前备份 profile、bundle、state directory、ledger 和 config。
- Importer 生成 `import/manifest.json`：源路径 digest、schema、计数、映射/不可恢复记录和 V2 首序列。
- 旧 state 仅在迁移只读路径出现；生产新核心拒绝直接加载。
- 回滚恢复旧 bundle 与备份，不把部分 V2 状态写回旧 layout。
- 未确认外部副作用保持 quarantine，不自动重放。
