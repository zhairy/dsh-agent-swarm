# DSH Agent Swarm 3.2.1 上下文准入与原生集成硬化

## 1. 背景

用户选择 OpenAI 官方 provider 的 `gpt-6.1-sol` 与 `reasoningEffort=max` 后，请求立即返回 `finish=length`，界面显示“已达到输出 token 上限”。复现表明模型、OpenAI API 凭据、协议适配和全新小会话均正常；问题会话在 DSH 中的回放测量约 `368,003` tokens，而官方 OpenAI 路由声明 `contextWindow=272,000`、`maxTokens=128,000`。模型切换只改变目标路由，没有改变现有会话历史，因此超大会话被送入较小上下文窗口后无法生成有效回答。

Swarm 3.2.0 没有在模型派发前执行上下文容量准入。该缺陷属于 Swarm 的路由治理缺口，但不是 OpenAI provider 故障，也不是 Swarm 接管了其他 DSH provider。

同时审核发现，3.2.0 是增量重构而非 PRD 全量完成：RouteEngine、Router/Worker、Watchdog 主要是独立模块或只读投影；`service.ts` 仍承担主要运行时；EventJournal V2 是旧账本的旁路镜像，尚不能独立重放恢复全部业务状态。3.2.1 因此定位为兼容性硬化版本，不宣称完成 3.2.0 的全部 strangler 迁移。

## 2. 目标

1. 在模型请求真正派发前测量当前会话上下文。
2. 每个候选路由扣除本轮输出预算和安全余量后，确认可承接现有会话。
3. 主模型超窗时按既有主备链自动选择上下文足够的模型。
4. 全链均不足时明确报错并保证“未调用模型”，避免等待提供方返回截断结果。
5. 宿主没有 `tokenMeter`、模型没有声明上下文容量时保持旧行为，不破坏 DSH 兼容性。
6. 记录被跳过的路由和容量事实，便于诊断。
7. 保留原生 `ask_user_question`、`todo_write`、`time-context`、`agent-instructions`、`jobs`、`goal`、计划模式与 Git worktree 的宿主所有权。

## 3. 非目标

- 本次不重写 `service.ts`，不删除旧状态兼容路径。
- 本次不把 `RouteEngine`、`Router/Worker`、`Watchdog` 强制切换为唯一运行时权威。
- 本次不改变 OpenAI 模型的宿主目录声明，也不把官方 OpenAI 路由伪装成 `openai-codex` 路由。
- 本次不自动压缩或删除用户会话；超窗恢复由用户选择新会话、分支、压缩或更大上下文模型。
- 本次不接管原生 `agent-team`、`todo` 投影或 `session-query` 后端。

## 4. 技术方案

```mermaid
flowchart TD
  A[Agent/request] --> B[既有 RouteState 候选选择]
  B --> C{tokenMeter 可用且会话可测量?}
  C -- 否 --> H[保持 3.2.0 行为]
  C -- 是 --> D[resolveModelInfo: contextWindow/defaultMaxTokens]
  D --> E{容量元数据有效?}
  E -- 否 --> H
  E -- 是 --> F[安全输入 = contextWindow - max(本轮 maxTokens, 默认 maxTokens) - 4096]
  F --> G{measuredTokens <= safeInput?}
  G -- 是 --> I[准入并派发该路由]
  G -- 否 --> J[记录 route/skipped 并尝试下一候选]
  J --> K{仍有候选?}
  K -- 是 --> B
  K -- 否 --> L[CONTEXT_RECOVERY_REQUIRED: 未调用模型]
```

实现点：

- `src/context-admission.ts`：纯函数容量判断与稳定错误文本。
- `src/host-contract.ts`：读取原生 `ctx.tokenMeter`、`ctx.llm.resolveModelInfo().context` 与 `defaultMaxTokens` 的可选契约。
- `src/service.ts`：在单个 AbortSignal 请求生命周期内缓存会话测量，将容量检查接入 RouteState。
- `src/route-state.ts`：候选路由必须先通过既有 metadata probe 与上下文准入；主模型和健康路由同样检查。
- 对话框选择的模型即使未列入角色备用链，也先作为本次准入候选检查；通过则尊重选择，超窗才进入声明备用链。
- `src/index.ts`：从真实 DSH context 注入 `tokenMeter`，不新增硬依赖。
- `src/util/errors.ts`：新增 `CONTEXT_RECOVERY_REQUIRED`。

安全边界：

- 测量或容量未知时 fail-open 到旧行为，避免旧 DSH 或第三方适配器被错误阻断。
- 错误信息只含 token 数量、窗口和建议，不读取或输出凭据、消息正文。
- 输出预算取 `max(本轮 maxTokens, 模型 defaultMaxTokens)`，避免省略 `maxTokens` 时低估保留量。
- 所有候选均不足时不设置普通路由链终态，用户修改模型或会话后可重新准入。

## 5. 原生插件适配矩阵

| 原生插件/能力 | 3.2.1 适配 | 所有权与边界 |
| --- | --- | --- |
| `dsh-tool-ask-user` | 保留工具；授权运行时读取 `userQuestions` 投影并识别开放问题 | 根会话负责提问；存活专家子会话按宿主规则不得直接提问，缺口交由天枢 |
| `dsh-tool-todo` | 保留 `todo_write` 与投影 | Todo 是单 agent 会话计划；Swarm Ticket/DAG 仍是任务和门禁真源，不复制或强写原生 todo |
| `dsh-time-context` | 保留标准预设行 | 宿主负责注入时间与浏览器时区；Swarm 不重复探测时间 |
| `dsh-agent-instructions` | 保留指令链 | 宿主负责 `AGENTS.md/CLAUDE.md` 发现与刷新；worktree 创建后随 Session cwd 生效 |
| `dsh-tool-jobs` | 消费 `ctx.jobs`、job 生命周期事件和租约 | 宿主拥有进程内作业与完成通知；Swarm 只做归属、结算和恢复判断 |
| `dsh-tool-goal` / goal seam | 绑定 goal owner/revision，受阻或停止时 disarm | 宿主拥有 goal 状态；用户仍通过原生控件或命令恢复 |
| `dsh-plan-mode` | 原样保留 | 计划审阅由宿主拥有；Swarm Planning Review 与 Ticket 门禁继续作为业务证据层 |
| `dsh-experimental-tool-worktree` | 守卫写操作前必须先创建并绑定工作树 | 宿主负责 Git 创建和 cwd 切换；Swarm 记录 task/attempt 绑定并禁止跨任务复用 |
| `dsh-tool-session-query` | 不强制启用 | 该包是 opt-in，standard 默认未挂载；避免读取私有会话文件或绕过工作区授权 |
| `dsh-experimental-tool-agent-team` | 只读投影 | 不接管宿主 agent-team 调度，避免双调度器竞争 |
| `dsh-token-meter` | 新增上下文准入消费 | 只读取测量，不影响压缩、UI 或 provider |
| `dsh-tool-schedule` | 保持宿主组合差异 | 专家预设不强行复制根会话定时能力；避免旧 DSH 缺包和权限扩大 |

## 6. 对 `dsh-superagent-prototype` 的差距结论

已吸收：

- Ticket 阶段投影与 Mandate `off/observe/auto` 纯规则。
- 失败事实、路由资格审查、事件过滤和 Worker submission 校验模块。
- JSONL V2 事件信封、摘要链、投影和旧账本镜像。
- Watchdog 对停滞、租约和未知副作用的只读判断。
- Router 工具写入边界和 Worker 身份/版本约束的设计。

尚未完成：

- `RouteEngine` 未成为运行时唯一路由权威，现有 `route-state.ts` 仍承担主要执行。
- `Router/Worker` 校验没有覆盖全部真实委派入口。
- Watchdog 没有定时接入服务生命周期和面板告警。
- EventJournal V2 没有独立快照、封片、滚动和完整崩溃重放切换。
- UI 仍是大型 `settings-page.js`，没有按领域拆分。
- 旧 TaskRecord/状态兼容路径仍保留。
- 主动 `off/observe/auto` 尚未完整驱动所有外部触发器。

这些差距进入后续版本，不在 3.2.1 中虚假标记完成。

## 7. 风险与回滚

| 风险 | 控制 |
| --- | --- |
| 旧 DSH 没有 `tokenMeter` | 服务可选获取；缺失时完全保留旧行为 |
| 第三方模型不声明上下文 | 元数据缺失时不阻断 |
| 测量结果偏大导致误拦 | 记录测量与容量；用户可切到更大窗口模型或新会话 |
| 路由安全检查遗漏健康主路由 | 主路由与回退路由统一经过 `contextChecks` |
| 运行中超大会话继续请求小窗口 | 全链不足时在 dispatch 前失败，不等待 provider 截断 |
| 与其他 DSH 插件冲突 | 只读取公开 seam，不修改 provider 目录、原生 todo/goal/time 状态 |

回滚：恢复 3.2.0 的 RouteState 接入即可关闭上下文准入；不涉及数据迁移。V2 Journal 与现有任务状态无需回退。
