# DSH Agent Swarm 3.3.2 运行时完整性与原生集成

## 1. 背景

3.3.1 在旧会话中出现两类实际故障：

1. Windows 上 `StateStore` 初始化尝试对目录执行 `fsync`，Node/NTFS 返回 `EPERM`，会话无法创建持久状态。
2. 旧账本中的 `workflow/checkpoint` 记录超过 EventJournal 单行 64 KiB；首次派生 V2 事件时异常穿透到宿主，Goal 创建后的每一轮都以 `Event exceeds journal line limit` 失败。

另有 PR #4 修复 EventJournal 活动尾为 `null`、标量或数组时绕过恢复路径的问题。该 PR 与 Issue #5 无关，但修复本身可以独立合并。

## 2. 目标

- Windows 使用明确的 best-effort 目录持久化语义，不再因目录 `fsync EPERM` 阻断会话。
- 旧账本迁移不因单条超大审计记录阻断模型调用；保留摘要、字节数、digest 和形状。
- 合并 PR #4 的 non-event JSON 尾部恢复，并验证封片损坏保持不可变。
- 对 DSH 原生 `ask-user`、`todo`、`time-context`、`plan-mode`、`goal`、`jobs`、`agent-instructions` 和 Git worktree 做只读投影，不复制其权威状态。
- 在任务视图和 doctor 中显示原生 seam 可用性及摘要。
- 发布 `3.3.2`，不升级 DSH/pi-ai 版本。

## 3. 修改范围

- `state-store.ts`：目录 durability 显式区分 `strict` 与 `windows-best-effort`；仅 Windows 上 `fsync` 的已知不支持错误返回 `unsupported`。
- `ledger-event-bridge.ts`：超过预算的 legacy payload 改写为 digest-bound 摘要，原账本文件不变。
- `event-journal.ts`：解析结果必须是非 null、非数组对象。
- `native-integrations.ts`：从 DSH 公开 projection/service 读取原生状态，严格截断和脱敏。
- `application/swarm-service.ts` 与任务视图：增加只读 `native` 投影。
- `doctor`：检查原生插件 seam 与当前平台 durability。

## 4. 不改变

- Ticket/Assignment、模型路由、额度、认证、fallback、Jev 和 DSH sandbox/approval 语义。
- `todo_write` 仍是宿主每一步的唯一计划工具；Ticket/DAG 仍是 Swarm 业务真源。
- `time-context` 仍由宿主注入；Swarm 只读取 projection。
- Git worktree 仍由可编辑 Worker 使用宿主原生工具创建和进入。
- Windows 不能提供 Node 目录 `fsync` 时，不会声称与 Linux 完全相同的掉电目录项持久化保证。

## 5. 原 3.2.0 PRD 完成度结论

3.3.2 不虚假宣称原 PRD 已逐项完成。生产路径已具备 TicketRepository、统一 RouteEngine、事件 journal、Worker 边界、Watchdog、有界 scheduler 和投影化任务视图；但仍存在以下明确差距：

- 主动 `off/observe/auto` 领域判定已实现，尚未接入统一的外部 Source/Trigger 适配器。
- 当前 StateStore 是业务主提交点，EventJournal 在提交后派生；不是“EventJournal 为唯一恢复源”的纯事件溯源架构。
- 独立 durable Outbox dispatcher、Source/Thread/Eval/Subscription 完整域、授权表和多来源会话尚不在生产路径。
- 这些差距进入后续版本，不在 3.3.2 中伪称完成。

## 6. 风险与验证

- 模拟 Windows `fsync EPERM` 与 Linux 同错误，确保只有 Windows 已知限制被吸收。
- 使用超过 64 KiB 的真实 ledger 形状测试摘要迁移，验证 EventJournal 不超行、digest 稳定且原文件不变。
- 验证 non-event tail、sealed corruption、100k replay。
- 验证原生 todo/time/plan/goal/jobs/tool 摘要的脱敏和缺失降级。
- 完整 typecheck、单元/对抗、Host 集成、provider contract、安全审计、发布闭包、本机部署和旧故障会话恢复测试。

## 7. 回滚

恢复 3.3.1 bundle 与 profile 备份。Windows best-effort 回退不新增持久格式；legacy 摘要事件可通过 StateStore 和原 ledger 重建，EventJournal 不重放外部副作用。
