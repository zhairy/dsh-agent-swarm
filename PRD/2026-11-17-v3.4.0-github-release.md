# v3.4.0 GitHub 发布与 rc.3 兼容包

## 背景与目标

用户已授权发布 GitHub v3.4.0，同时发布涉及的第三方兼容包、补丁、已知问题和迭代计划。发布对象为 zhairy/dsh-agent-swarm，目标宿主 DSH 0.2.2-rc.3。本轮不升级宿主、不重启在役服务、不重放用户历史任务。

## 修改范围

- 发布说明、兼容矩阵、许可证/来源清单、已知问题及路线图。
- 发布归档包含 Swarm、可合法分发的第三方兼容组件、精确补丁清单、安装/校验工具和 Python 依赖锁。
- 公开验证摘要只含测试范围、版本、通过/跳过数和文件摘要，不含账号、认证数据、历史正文、会话标识、机器路径、私有日志或现场截图。
- 本地开发记录保留。公开 release 分支使用独立 Git tree/index 排除本轮私人部署 PRD，避免把私人记录通过开发分支历史上传；不建立第二开发工作树、不改写既有分支。

## 数据结构与 API

不改变 Swarm 业务 API、事件格式或数据库。兼容包 manifest 记录组件名称、版本、上游来源、许可证、归档 SHA-256、补丁前后文件 SHA-256及运行依赖。新第三方许可证文件只补足分发声明，不改变其运行代码。

## 执行计划

1. 核对当前源码、精确已验证安装包、第三方闭包、许可证与上游版本。
2. 生成完整兼容归档与公开说明，检查相对导入闭包、秘密/私人数据排除、原版到修补版的校验和回滚。
3. 复用仍匹配的验收证据，补充此次打包和许可证相关核验、必要的源码测试与依赖审计。
4. 建立公开 release commit，通过GitHub连接器提交分支，创建并合并 PR；以合并 commit 为 v3.4.0 tag。
5. 发布包由受测源码构建；用源码逐文件SHA绑定tag commit，并核对运行代码一致。限定版本的GitHub Actions只在可信main运行，使用内置临时token创建draft、上传核验后发布，不读取本机凭据；资产来源固定为不可变commit。
6. 回读 tag、Release 与全部附件，下载逐字节校验后记录发布回执。

## 风险与边界

- 核心 Swarm 兼容与第三方组件的功能验证分别列出，启用/目录存在不等于全部业务功能通过。
- 只有许可证与来源可确认的组件进行再分发；本机私有 preset、凭据和会话配置不打包。
- 精确 SDK 补丁遇到未知版本/摘要拒绝；兼容包不能作为未来 DSH 版本的通用升级工具。
- Release 公布用户已批准的成果，规划方向不冒充已实现功能；不承诺供应商额度或无人值守长程任务保证。

## 验证方式

完整资产 manifest/SHA256SUMS、解包内容和许可证检查、补丁正反向与未知摘要拒绝、静态相对导入闭包、对应单元/Node/Host测试、GitHub tag/PR/Release 回读及每个公开资产的下载字节校验。

## 回滚方案

发布前失败时不修改远端正式 tag/Release。draft 资产未全部核验前不设为正式版本。发布后若需修复则保留既有版本与校验和，使用补丁版本公告处理，不移动已发布 tag 或静默覆盖包。此次发布不修改在役 profile，因此不需要回滚用户运行数据。
