# PR #14 发布附件分支合并冲突修复

## 背景与目标

PR #14 的来源分支只保存 12 个发布附件，未保留 main 的源码树。直接合并会删除源码，并产生 77 处修改/删除冲突。目标是保留源码与附件，将 PR 修正为仅新增发布附件及本说明。

将 main 合入 release-assets/v3.4.0-overlay-sync；所有 main 文件、模式及 blob 保持原样，12 个 assets 附件保持原字节。保留双亲提交，不改写分支历史；原发布工作流仍固定既有不可变资产 commit。

仅新增 assets 下的原发布附件与本 PRD；不新增依赖、API、数据库字段或数据迁移。此次只更新 PR 分支，GitHub release 和产品 tag 不变。

不能只处理 Git 标注的冲突文件：未修改的源码也可能被静默删除。因此核对 main 全部文件以及所有附件的路径、模式和对象摘要，要求最终 PR 零删除、零源码修改；检查修复后的分支可直接与 main 合并。

运行 Node 与发布前置测试；附件按既有发布计划核验 SHA256，兼容总包按精确 rc.3 SDK 核验文件、声明入口、相对导入及 overlay。保留本轮原冲突记录与验证日志。

## 回滚

通过新的反向提交回退本次合并修复，保留原历史与附件提交；不移动产品 tag，不覆盖本机工作树及用户未提交文件。
