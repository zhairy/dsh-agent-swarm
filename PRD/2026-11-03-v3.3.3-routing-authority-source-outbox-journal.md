# DSH Agent Swarm 3.3.3：人工选模、角色恢复与事件源完成

## 1. 背景

旧会话中出现两类生产问题：

1. 用户在 DSH 模型选择器明确选择 `openai/gpt-6.1-sol` 后，`swarm_task_card` 的高风险规则自动启用根升级链，造成连续跨供应商切换。
2. 旧会话恢复时，运行时可能继续使用旧的静态 preset 或工具 scope；根会话作为 Router 理应禁止写入，但旧子会话也可能因 role 缓存未刷新而遇到错误的权限面。

同时，原 3.2.0 PRD 仍有三个明确缺口：

- durable Outbox；
- 统一 Source/Trigger 入口；
- 以 EventJournal 为唯一恢复源的纯 journal-only recovery。

## 2. 目标

- 显式人工选模优先于任务卡风险规则。真实 provider 调用的额度和认证 fallback 保留。
- 旧会话恢复以当前 Host `agentPreset`/projection 为准重建 root/subagent 角色、提示词和工具面；角色变化时撤销旧 scope 并重新限制，角色与执行授权不一致时 fail closed。
- EventJournal 分块记录 state snapshot/patch/commit，StateStore 成为可删除的物化缓存；`events.journal=true` 时状态持久性不依赖本地 `persistence.enabled`。
- Source、Trigger、Thread、Subscription 决策、Outbox 和 delivery receipt 均可从同一 EventJournal 重建；人工 follow-up 与推断更新以 L1 context 绑定活动 Ticket。
- 发布 `3.3.3`，兼容 DSH `0.2.0-rc.2` 至 `0.2.1-rc.5`，不升级宿主。

## 3. 修改范围

- `src/application/routing/engine.ts`：记录“Host 人工选择”与自动 request header 的区别。
- `src/application/swarm-service.ts`：人工选择存在时抑制自动 root upgrade；角色重新绑定；Source/Outbox service wiring。
- `src/runtime.ts`：使用当前 Host role，而不是静态 preset role；旧 child prompt/scope 不匹配时重建。
- `src/state-store.ts`：可选 `journalOnly` materialization、提交前事件 observer、跨布局迁移事件。
- `src/state-journal.ts`：state snapshot/patch/encoded-change 分块、链校验、未完成尾部忽略。
- `src/domain/sources/`：Source instance、Trigger strength、`off/observe/auto` 决定、adapter 注册。
- `src/outbox.ts`：与 enabling fact 同行持久化、delivery/retry receipt、幂等 handler ID。
- 任务页增加 Source/Outbox 有界只读摘要。

## 4. 数据与兼容

- Event schema 继续使用 `dsh-agent-swarm/event/v2`，新增 fact 类型而不改变旧事件字段。
- 首次运行 3.3.3 从现有 StateStore/route-health sidecar 种入 journal；之后 state mutations 先写 journal chunk group，complete marker 落盘后才物化 StateStore。启用 `events.journal` 时，本地缓存关闭不会撤销 Journal durable authority。
- 未完成的 journal chunk group 不参与恢复。
- 旧 StateStore、ledger 和 sidecar 保留为迁移输入/回滚材料；journal-only 模式不读取旧物化状态。
- Outbox 只登记明确 effect kind；未注册 handler 不执行外部动作。注册 handler 必须自行按 `effect.id` 幂等；`RECOVERY_REQUIRED` 类错误进入 blocked，等待重启或显式 dispatch，不耗尽为永久失败。
- 用户显式选模阻止任务卡自动 root upgrade；真实请求失败仍按 RouteEngine 主备链回退。

## 5. 风险与边界

- 状态事件会保留完整私有状态内容以获得无损恢复。EventJournal 文件继续使用 `0600` 权限，凭据字段仍由 StateStore validator 拒绝；不得向 Release 或公开讨论上传 journal。
- Source adapter 重启后需要重新注册代码实现；Source instance 与 Trigger/Decision 从 journal 恢复。
- Auto 模式只产生 durable `ticket-intent`，不重放外部副作用。具体 connector 的写操作必须通过已注册、幂等的 Outbox handler。
- DSH 原生权限仍是最高边界。Router 读写限制、subagent tool scope、worktree 和 approval 不能由模型输出解除。

## 6. 验证

- 人工选模 + 高风险任务卡：不切换 root upgrade；真实 request error 仍能 fallback。
- 旧持久选模恢复：同样抑制自动升级。
- 旧 child preset 与当前 projection 不同：提示词/tool scope 使用当前 role。
- 删除整个 StateStore 目录：从 journal 恢复 task、delegation、binding、control、context、budget、route health 和 runtime。
- Source：self/plugin 过滤、explicit/inferred、off/observe/auto、重复 external ID。
- Outbox：pending、handler failure、backoff、retry、delivery receipt、重复 dispatch 幂等。
- 全量 typecheck、build、unit、Host integration、真实 DSH reload、旧会话回归、provider 兼容和两轮正反审计。

## 7. 回滚

恢复 3.3.2 bundle 与 profile。新 journal state facts 不应被旧版本解释为业务状态；旧版本可继续使用迁移前 StateStore 备份。未完成 Outbox effect 不自动重放。若新 journal 出现链错误，停止写入并使用 journal 只读取证和迁移前 backup，不把旧 StateStore 伪装成最新状态。
