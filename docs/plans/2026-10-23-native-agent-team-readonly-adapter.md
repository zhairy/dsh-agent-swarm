# 原生 Agent Team 只读投影适配计划

日期：2026-10-23

实现状态：3.1.0 已完成第 1、3、4 项。`nativeTeamProjection` 默认关闭，只读取宿主已有的 `agentTeam` 投影；会话头部镜像最多显示 32 个成员和 100 个任务，可打开已有成员会话。未调用 `spawn_teammate`、未修改共享任务、未启用双向同步。第 2 项 `swarm.projection` 未实现，继续由宿主投影提供只读数据，避免新增第二份任务事实源。

## 结论

百工继续是任务、委派、attempt、租约、门禁和验收的唯一事实源。原生 Agent Team 只吸收：

- 会话顶部成员与任务投影；
- 成员会话导航；
- 状态推送；
- 执行步骤边界通知。

不吸收 `spawn_teammate`、原生 `complete` 或任何可绕开 `swarm_delegate` 的控制面。当前实验包与 DSH 版本绑定，且公开 API 缺少 preset、路由和 output schema 装配参数，因此 3.1.0 只做默认关闭的投影契约与客户端占位，不建立双控制面。

## 分层边界

| 层 | 百工 | 原生 Team 适配层 |
| --- | --- | --- |
| 创建任务 | `swarm_task_card` | 只读展示，不创建 |
| 委派与 attempt | `swarm_delegate` + 租约 | 只读导航，不调用 `spawn_teammate` |
| 完成与失败 | 百工状态机 + 证据门禁 | 只展示状态与步骤边界 |
| 模型路由 | 百工角色链 | 不覆盖 preset/provider/model |
| 验收 | `swarm_accept` | 不调用原生 `complete` |

投影记录只允许以下字段：会话 ID、任务 ID、角色、状态、当前步骤、最近更新时间、只读导航 URI。禁止复制消息正文、提示词、凭据、私有材料和批准快照。

## 3.1.0

1. 在设置中保留 `nativeTeamProjection` 开关，默认 `false`。只有宿主提供稳定投影接口并且用户显式开启时才注册槽位。
2. 定义 `swarm.projection` 只读 RPC：按当前根会话返回任务摘要、成员摘要、active/blocked 计数和 `updatedAt`。数据来自现有任务状态，不新增第二事实源。
3. 客户端只注册顶部徽标和成员导航占位；点击仅切换到已有百工子会话，不发送 spawn、complete、continue 或模型覆盖命令。
4. 步骤边界通知去重键为 `(taskId, delegationId, stepIndex, status)`，只推送状态变化；队列有上限，失败不阻断百工执行。
5. 原生 API 缺失、版本不匹配或 schema 校验失败时，投影自动降级为不显示；不回退到调用未声明接口。

验收：关闭开关时没有任何 Team 注册或 RPC；开启后只读；原生 Team 卸载后百工工具、门禁与恢复不受影响；所有调用在隔离宿主中验证。

## 双向同步前置实验

只有以下六类实验全部通过并形成默认关闭的治理开关，才评估双向同步：

1. 准入旁路：原生调用不能绕过百工门禁。
2. 双状态冲突：两个控制面同时变更时的幂等与收敛。
3. 控制竞争：同一成员、同一 attempt 的 CAS 与租约。
4. 隔离与盲审：原生投影不泄露作者与评审者上下文。
5. 版本禁用：宿主或插件升级使实验失效时自动停用。
6. 收益基线：与纯百工控制面相比，延迟、失败率和用户操作步骤有可重复改善。
