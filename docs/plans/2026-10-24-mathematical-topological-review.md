## 3. 可以成立的数学命题及其边界

### 3.1 安全性：硬守卫只保证合法迁移

定义权威迁移函数：

\[
\delta(s,\operatorname{accept}(r))=\begin{cases}
\mathrm{ACCEPTED},&\operatorname{Current}(r,s)\land\operatorname{Authorized}(r)\land\operatorname{EvidenceValid}(r,s)\land\operatorname{AllMandatoryGates}(s),\\
\mathrm{REJECTED\_TRANSITION},&\text{否则。}
\end{cases}
\]

它证明的是“没有这些条件就不能进入完成状态”，不能证明外部模型结论、测试覆盖或业务需求绝对正确。威胁模型假设宿主身份、校验实现和受限持久层可信；宿主被攻破不在同一保证内。

“不可绕过”具体覆盖插件支持的 Agent 工具、服务 API、原生适配及正常状态迁移入口；拥有操作系统 root 权限的人工维护、直接改写受限存储或加载恶意插件不属于该 API 安全证明。需要受支持的维护恢复入口、写入围栏和审计，但不能宣称限制了宿主特权所有者。

建议将 `verification_receipt_id` 解析为服务器私有记录，记录绑定：`rootSessionId/workspaceId/taskId/nodeId/attemptId/requestRevision/cardRevision/workflowRevision/questionVersion/policyVersion/artifactDigest/evidenceDigest/issuer/revocationState`。Git commit SHA 只在适用时附带，未提交工作区仍由产物摘要覆盖。

签发与消费前必须重新核对当前版本和产物；撤销、过期、跨任务、错工作区、旧 attempt、证据不全均拒绝。同一合法完成重复调用返回既有结果，不能重复产生副作用。签名、随机 ID 或 TypeScript 类型都不能替代签发权限和查表验证。单宿主可先用受限记录 + 不透明 ID，不必为了形式新增密钥基础设施。

### 3.2 相邻距离趋零不蕴含收敛

令 \(x_t=\sin(\log(t+1))\)。由正弦函数的 Lipschitz 性，

\[
|x_{t+1}-x_t|\le\log(t+2)-\log(t+1)\to0.
\]

但取接近 \(e^{\pi/2+2k\pi}-1\) 与 \(e^{3\pi/2+2k\pi}-1\) 的整数子序列，函数值分别趋近 1 与 −1，因此整个序列不收敛。这比“趋近但永不等于某值”更直接否定“相邻变化小便是固定点”。固定错误输出的相邻距离也等于零。

若使用

\[
p_t=w_g\Delta g_t+w_d d_t+w_e\Delta c_t,
\]

必须规定量纲、归一化、缺测、正负号及独立证据来源。负的质量增量可能与正的新意抵消；“结果变差”应有独立退化标志，不能因加权和为零被描述成稳定。余弦差不是 Shannon 熵；没有明确随机变量与分布不能称为语义熵证明。没有正定势函数及下降条件，不能称为 Lyapunov 证明。

建议客观证据优先，向量相似度仅影子指标；低变化 + 已无运行中工具/外部等待 + 重复决策证据，才暂停当前轨迹并触发有界恢复。未满足验收时不得以早停生成成功。

### 3.3 全局新意的有限终止命题

固定 epoch、固定投影 \(q\) 与有限判定状态集 \(S\)，\(|S|=N\)。初态 \(q(s_0)\in S\)，每个获准后继必须满足

\[
q(s_{t+1})\notin\{q(s_0),\dots,q(s_t)\}.
\]

根据抽屉原理最多有 N 个互异获准状态，即初态之后最多 N−1 次新状态迁移。若用度量空间的 ε-packing number，必须所有已访问状态两两距离大于 ε，不能仅要求相邻距离非零。结论只是当前固定 epoch 的有限轨迹，不是任务正确/必然成功。

实现契约：全局签名排除时间戳、轮次号和自述改写噪声；绑定客观产物、已验证证据槽位、未解决 finding、稳定阶段谱系和图语义。摘要碰撞疑似时比对规范原文；近似邻居相似不能当作精确等价关系。历史索引达到配置容量时进入 `EXHAUSTED`/归档后显式恢复，不能静默删旧签名后继续宣称全局保证。

固定长度哈希的有限位数意味着形式上有限，但其容量巨大，且存在碰撞；不能把这一事实包装成实用语义终止证明。无限新产物摘要、无限 epoch 或无限授权重规划也会绕开单 epoch 结论，因此自动恢复谱系另有有限激活约束，真正的新需求由真实来源创建新阶段。

### 3.4 窗口检测下界的正确表述

明确可验证的弱结论是：**只检查最近 w 个状态中是否重复**的检测器，会漏过周期为 w+1 的循环。例如 w=3，`0,1,2,3,0,1,2,3,…` 的当前状态从不出现在前 3 个状态中。

若声称所有窗口检测器都必然漏检，需要说明其仅有局部窗口、无全局计数/历史记忆、需避免误停合法全新轨迹等条件。会在固定轮次无条件停止的检测器显然能终止；它通过保守误停换取终止，不能被上述论证否定。本文不引用未经定位的强下界定理。

### 3.5 DAG 的有限激活命题

固定 DAG 有 V 个节点，每节点初次执行 1 次，最多 r 次重试，且恢复不额外重置该额度、调度器只激活获得准入的节点，则该图最多激活 `(r+1)V` 次。Kahn 的无环检测/拓扑排序本身时间 O(V+E)、空间 O(V+E)。若一个阶段最多允许 m 次重新规划、各图大小至多 V，且恢复已计入 r 或不额外产生激活，粗上界才是 `(m+1)(r+1)V`。若每个规划阶段至多 h 次恢复、每次恢复后至多 A 次计算激活（含诊断），则改为 `(m+1)(h+1)A`，另加有限重规划/恢复和控制迁移；不能允许恢复补充新额度却仍沿用原公式。

有环的“评审→修复”不要直接塞入 DAG。展开为 `review_1→fix_1→review_2→…` 的有限层，每次激活仍校验证据与依赖；最终失败走 `ESCALATE`，最后一次通过走正常验收。禁止“固定第 2 次结束后无论通过失败都升级”的无条件规则。

图无环不保证 I/O 返回，也不保证调度公平或任务成功。长期训练、读取或用户答复进入 `WAITING_TOOL/WAITING_EXTERNAL/QUESTION_PENDING`，保存运行句柄和检查点，不进行空白 LLM 推理；恢复需要真实完成事件、用户回答或显式取消。等待时间本身不消耗语义新意，不视为循环。

### 3.6 审核边的观测收益

`下一版通过率 − 当前通过率` 至多是观测相关：代码变更、任务难度、其他审查和测试集变化均可能混杂。两个周期不能普遍证明“统计不显著”或“零因果效果”；同样，`p>0.05` 也不证明无效果。

首版只对可选咨询边记录任务类型、独立指标、版本、成本和干预；在固定轨迹/匹配样本上评估收益与误停，再决定降优先级或换审查者。强制验收、权限、风险、盲审、依赖契约边永不被自动修剪；任何改变有效依赖的调整生成新图版本并重新准入。

## 4. 确定性反例与本轮实测

在 `.work-v3` 运行以下只读命令，可复核当前 checkpoint 的边界，不修改任务状态：

```bash
node --input-type=module <<'JS'
import assert from 'node:assert/strict'
import { getCheckpoint } from './lib/checkpoint.js'
const base = { taskId: 'T-math-audit', cardRevision: 1, workflowRevision: 1, evidenceRefs: [], unresolved: ['A'] }
let same, alternating, changedVersion
for (let i = 0; i < 6; i += 1) {
  same = getCheckpoint({ ...base, roundId: String(i) }, same)
  alternating = getCheckpoint({ ...base, roundId: String(i), unresolved: [i % 2 === 0 ? 'A' : 'B'] }, alternating)
  changedVersion = getCheckpoint({ ...base, roundId: String(i), cardRevision: i + 1 }, changedVersion)
}
assert.equal(same.convergence.blocked, true)
assert.equal(alternating.convergence.blocked, false)
assert.equal(changedVersion.convergence.blocked, false)
const w = 3
const cycle = Array.from({ length: 12 }, (_, i) => i % (w + 1))
assert(cycle.every((x, i) => !cycle.slice(Math.max(0, i - w), i).includes(x)))
console.log(JSON.stringify({ same: same.convergence, alternating: alternating.convergence, changedVersion: changedVersion.convergence, windowEscape: true }))
JS
```

2026-10-24 实测输出：同问题连续 6 次的 `repeatedWithoutProgress=5, blocked=true`；A/B 交替及每次修改合同版本都为 `0,false`；w=3 的 4 状态循环确实逃过该局部去重规则。这是当前局部 checkpoint 的能力边界，不证明任何现有验收门禁已被绕过。

数值例：`abs(sin(log(1000001))-sin(log(1000000)))=3.1613779361006067e-7`。数值只展示相邻变小，非收敛结论来自上文明确的子序列反例。

## 5. 时间、空间与工程取舍

记 B 为规范结构字节数，H 为历史签名数，U 为未解决问题数，R 为累计证据数。

| 机制 | 时间 | 空间/边界 |
| --- | --- | --- |
| 规范编码与摘要 | O(B)，对象键排序另计 O(Σ k log k) | O(B) 临时分配；不应每条 token 执行 |
| 精确签名哈希索引 | 摘要已知时平均 O(1) 查找/插入，最坏界依实现 | O(H)，碰撞回查另计；保留容量与持久化恢复策略 |
| 全历史 ε 近邻的直接比较 | 每轮 O(Hd)，d 为向量维数 | O(Hd)；首版不放在调度热路径 |
| 当前 checkpoint | 证据重建 O(R)，未解决列表排序 O(U log U) | O(R+U)；每轮新增一条时长期累计复制可能 O(T²) |
| Kahn 标准实现 | O(V+E) | O(V+E) |
| 当前完整工作流校验 | 后继数组重复复制 O(Σ degree²)，多次祖先遍历 O(V(V+E))，另计门禁匹配 | 已有 V≤32/E≤64 上限；优先索引复用，避免过度工程化 |

只有增量更新已改变的结构、复用未变摘要和有界状态签名索引，才可能使常见调度判定接近常数成本；首次读取、规范化、证据验证、全图校验和恢复仍有线性工作。不得宣称整个插件已优化到 O(1)。

已确认采纳：完整版本的 bindingKey 与排除纯版本噪声的 noveltyKey 分离；固定有限投影与全历史前提；无工具主持轮次检查；真实等待不发 LLM；最后评审通过正常验收；强制门禁不剪；观测收益不冒充因果；0/n 观测不证明零风险；未知宿主能力不伪造；不因凭证改造重新制造“修复审核服务必须先通过同一坏审核”的维护死锁。

发现两处**在数学有限性主张进入实施基线前需修正文义**：

1. **新建等待句柄不得成为秩下降的例外。** 3.1.3 的“自动动作严格下降或产生真实等待句柄”存在逻辑缺口：如果每次都创建新的真实 API/工具句柄，却不减少任何计数，可以保持相同 R 而无限创建工作。应改为：新建工具、询问、评估或恢复运行必须归属于一次已扣计数的激活；只有对**同一个已登记在途句柄**的被动等待/事件观测可以保持 R，且不触发新 LLM 或重发工具。句柄被取消/结束后，换新句柄需再次经过计数与幂等准入。首次合法询问也需保证不被零剩余计算预算阻挡，可使用独立预留控制额度，但不得反复新建问题逃逸。
2. **上界公式必须覆盖恢复重置。** 若恢复减少第二分量同时可重置第三分量，`(m+1)(r+1)V` 只有在恢复不额外重置该节点激活预算、或所有恢复已计入 r 时成立。若每个重规划阶段最多 h 次恢复，每次最多 A 次计算激活，则粗计算激活上界为 `(m+1)(h+1)A`；另加有限恢复/重规划控制动作。不能只写“额外恢复计入”而又允许它恢复未计入的新激活额度。若不需要数值上界，保留严格良序下降证明并明确重置值有限也可以。

上述计数属于一次自动流程的控制轨迹，不是给 Jev 增加费用/时间/调用配额。一个已准入阶段内部的正常独立 Jev 判断仍遵守用户策略；重复不变证据不能通过无限新运行逃避流程守卫。

未发现其余必须阻断文档评估的设计缺陷；实现前仍必须核对实际宿主暂停/恢复能力和事务提交语义，本文不将计划视为运行验收通过。

### 修正后结论（2026-10-24）

已重新逐字核对 3.1.3 第 5 节，两项发现的文义均已解决：

* 新建句柄必须归属已扣计数的激活或独立有限控制预留，同一已登记句柄的被动等待才可保持 R；结算迁移单调有限。首次必要询问、取消和安全结算具有有限预留，既不制造零计算预算死锁，也不能无限补充预留来创建新工作。
* 无额外恢复激活时才使用 `(m+1)(r+1)V`；恢复可重置激活时使用 `(m+1)(h+1)A` 并另计有限控制迁移。本专项第 3.5 节也已同步相同前提。

据此，四份方案在所述可信宿主、固定阶段、有限控制初值/合法重置和真实等待不重发的前提下，可以进入后续实施。这里的有限性是编排控制激活轨迹的条件性结论，不是对每个外部服务、用户回答或开放研究目标有限时间成功的保证。原发现及其修正理由保留用于实现回归；真实宿主实现、测试和发布仍需独立验收。
