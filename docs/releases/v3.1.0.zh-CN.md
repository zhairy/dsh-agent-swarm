# dsh-agent-swarm v3.1.0

## 🐛 问题修复

- 修复 GitHub Issue #1：长会话或分页加载的事件窗口缺少 `request/header` 时，`swarm-model-call` 的 `start()` 不再返回 `undefined`。隐藏占位继承上一状态，渲染层丢弃该节点，宿主事件订阅器不会在“调用模型”处中断；后续消息可以继续显示。
- 隐藏占位不会让下一条实际调用误报“切换模型”；普通会话的 `assistant/attempt` 同样不会再中断事件流。
- DeepSeek 的 `The content[].thinking ... must be passed back` 错误归类为 `protocol_incompatible`。当前请求立即回退，故障路由被隔离，避免同一会话反复命中不兼容模型。

## 🎨 体验优化

- `swarm_status` 新增 `blockedRecovery`：根据真实失败、规划状态、检查点、未满足门禁和验收缺口，区分协议不兼容、路由耗尽、规划服务故障、连续无进展、缺门禁与验证缺口，并给出推荐角色、证据和下一步。
- 天枢在任务受阻或宿主报告本轮失败时先读取 `blockedRecovery` 与 `recovery.current.lastFailure`；最多委派一次只读诊断或对应门禁角色，不通过重复改卡、重复评分或重放业务写入制造进展。
- 失败提示新增 thinking 协议不兼容说明，明确需要切换兼容路由并保留任务状态。
- 新增 DSH 原生 Agent Team 只读镜像（默认关闭）：可查看成员、共享任务、实时状态、owner、依赖和写入范围，并打开成员会话；不创建成员、不修改共享任务，也不绕过百工门禁。

## ⚠️ 其他变更

- 安装文档补充 pnpm 11 的本地 tarball 说明：使用 `minimumReleaseAgeIgnoreMissingTime: true`，只忽略缺少 registry 发布时间的本地包；`minimumReleaseAgeExclude` 只接受精确版本，不能写 semver range。
- 新增 `scripts/install-profile.mjs`：校验 tarball 后解包到内容摘要目录并改用 `link:` 安装，完全不依赖 registry 元数据。
- `lib/client.js` 明确标记为生成 bundle；事件投影拆到 `client/model-events.js`，React 展示层保留在 `client/model-display.js`。
- 四层自我进化仍只提供分阶段计划。3.1.0 不自动修改提示、工具或工作流。
- 审核阈值、角色权限、执行门禁、证据要求和 DSH 兼容范围保持不变。
