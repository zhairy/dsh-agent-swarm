## ✨ 新增功能

- 增量分片存储：状态按顶层段拆分成分片，每次提交只编码、哈希并写入「发生变化的分片」，主写入路径（任务卡、委派、绑定、消息、经验）的延迟不再随状态体积线性增长；0.25 → 16 MiB 实测增量提交中位 0.029–0.122 ms。
- 日志新增 v2 行格式：携带段布局指纹与分片根哈希，增量行只记录变更分片；2.5.x 写出的 v1 全量行仍可完整恢复，并在其后续写 v2 行。用不同段布局打开同一状态目录会被明确拒绝，不会静默误读。

## 🎨 体验优化

- 大状态（长任务、多委派、大量材料）下的写入延迟显著下降：同一台机器同一轮实测，16 MiB 状态的全量提交中位为 2.5.2 60.73 ms、2.6.0 87.41 ms，增量路径 0.110 ms 且与体积无关（约 790 倍）。
- 业务校验（validateFeatureState）成本与 2.5.x 相当：1000 委派 0.94 → 0.98 ms、4000 委派 2.36 → 2.29 ms、100 任务 / 4000 委派 1.67 → 1.65 ms；校验对已冻结的材料跳过摘要重算，不引入额外开销。
- 整份快照的写入周期从每 16 次提交放松到每 64 次（增量日志下 journal 增长缓慢，恢复成本不增）。

## ⚠️ 其他变更

- 单向升级约束：2.5.2 及更早版本无法解析 v2 日志行。回滚前必须先用 2.6.0 打开状态目录触发一次整份快照，或恢复升级时备份的状态目录（本机为 `~/.dsh/backups/agent-swarm-pre-2.6.0-20261016-170720`）。
- 全量提交路径（快照与兼容路径仍使用）因分片遍历与哈希组合开销比 2.5.2 慢约 1.27–1.54×；主写入路径不受影响。
- 持久化 4 MiB / 内存态 16 MiB 护栏保持；分片数随记录数增长，段内二级分片等治理列入后续版本。
- 基准为开发机内存态测量，不是 NAS、端到端、LLM 成本或 Token 收益基准。
