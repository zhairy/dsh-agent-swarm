# dsh-agent-swarm v3.1.0

## 🐛 Fixes

- Fixed GitHub Issue #1: `swarm-model-call` no longer returns `undefined` from `start()` when a long or paginated event window begins without `request/header`. A hidden placeholder inherits the previous state, the renderer drops the node, and the host event subscription continues.
- The hidden state does not create a false "model switched" row for the next real attempt. Ordinary sessions using `assistant/attempt` are protected by the same contract.
- DeepSeek's `The content[].thinking ... must be passed back` error is classified as `protocol_incompatible`; the request fails over immediately and the incompatible route is isolated.

## 🎨 Improvements

- `swarm_status` now exposes `blockedRecovery` with the failure cause, evidence, recommended roles and next action for protocol failures, route exhaustion, planning-service failures, no-progress checkpoints, missing gates and verification gaps.
- Tian Shu reads `blockedRecovery` and `recovery.current.lastFailure` when a run fails or a goal is blocked, then performs at most one bounded diagnosis or gate-specific delegation instead of repeating cards, scores or business mutations.
- Failure hints explain the thinking-protocol incompatibility and require a compatible fallback route.
- Added an off-by-default, read-only native DSH Agent Team mirror. It shows existing members, shared tasks, live status, owner, dependencies and write scopes and can open member sessions; it never creates members, edits tasks or bypasses swarm gates.

## ⚠️ Other changes

- Installation docs use pnpm 11's `minimumReleaseAgeIgnoreMissingTime: true` for local tarballs. It skips only packages whose registry metadata has no publish time; `minimumReleaseAgeExclude` accepts exact versions and rejects semver ranges.
- Added `scripts/install-profile.mjs`, which validates a tarball, unpacks it into a digest-addressed local bundle and installs it with `link:`, avoiding registry metadata.
- `lib/client.js` is explicitly marked as generated; event projection is split into `client/model-events.js`.
- Four-layer self-evolution remains a staged plan. Version 3.1.0 does not auto-modify prompts, tools or workflows.
- Review thresholds, role permissions, execution gates, evidence requirements and the supported DSH range are unchanged.
