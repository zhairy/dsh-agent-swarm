## ✨ 新增功能

- **执行前编排**：任务卡通过后、委派开始前，先产出结构化的编排方案——复杂度级别（小型单点 / 中型 2–3 条并行工作流 / 大型先立契约再并行切片）、拆分角度、子任务清单（角色、依赖、交付物）、并行组与必须串行的依赖链、风险项，以及一张编排 Mermaid 图。
  - 拆分角度覆盖 13 种常见解耦视角：技术分层、业务闭环切片、领域边界、数据所有权、稳定基座先行、部署单元、端侧/界面、接口契约先行、难点与风险隔离、按团队技能、业务流程状态机、资源特征、变更频率/规则引擎；每条角度都由任务卡里的事实（范围与验收条数、`flags`）推导，可复核。
  - 规则给出确定性基线，Jev 只在中小型以上任务上判断「复杂度」与「是否值得拆」（`choice` + `noul` 两题）。答案缺项或越界时回退规则，并把来源标成 `jev-fallback`，绝不假装判过。小型任务不消耗 Jev 调用。
- **编排视图**：图表新增第 6 个视角「执行前编排」。它与执行进度无关，只画拆分决策与依赖/并行关系；旧任务没有编排记录时不产出该视角，原有五个视角不受影响。
- **可操作的未知任务报错**：`未知任务：T-1` 现在会列出当前会话已知任务，并说明任务卡按根会话与工作区隔离（DSH 重启或切换会话后需用 `swarm_task_card` 重新创建）。
- **插件位置披露**：`swarm_status` 输出插件的版本、源码目录与构建产物目录，并在工具描述里说明本仓库源码在 `src/`、构建产物在 `lib/`、没有 `dist/` 目录——此前 agent 需要读实现时只能猜路径，`rg .../packages/dsh-agent-swarm` 与 `dist/*.js` 这类猜测会直接失败。

## ⚠️ 已知边界

- **编排只做决策**：本轮不改变既有委派调度（DAG 仍由天枢按就绪节点逐步执行）。并行能力依赖天枢按 `parallelGroups` 连续发起委派，插件不替宿主并行调度。
- 维度选择以规则为主，Jev 只调整投入级别；这不是「AI 自由编排」，而是可复核的规则 + 有界判断。
- 编排方案写在任务记录里，旧状态没有该字段，读取时按「无编排」处理。
