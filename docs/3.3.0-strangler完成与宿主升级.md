# 3.3.0 Strangler 完成与宿主升级

3.3.0 完成原 3.2.0 PRD 中剩余的生产路径接管，并把已验证的本地宿主升级到 DSH `0.2.1-rc.5` 与 `@earendil-works/pi-ai@1.5.0`。本版不改变 14 个角色路由键、主要工具名、供应商认证、额度、模型资格、主备回退或 DSH sandbox/approval 的权威关系。

## 运行时边界

- `src/service.ts` 只保留组合门面；实际组合根位于 `application/swarm-service.ts`。
- Host Guard、Math、Context、Project Files、Mailbox 和 Experience 使用独立 application use case。
- DSH 子智能体版本差异进入 `adapters/dsh-host/subagent.ts`，业务层不再直接判断宿主启动协议。
- Router 默认 `workspaceWrites: deny`。天枢只规划、授权、路由和派发；写文件、运行命令和创建工作树交给 Worker。
- Assignment 提交同时校验 Ticket、Assignment、request/card/workflow revision、input digest 和当前 workspace lease epoch。
- Watchdog 按 Assignment 心跳、lease 和未知副作用生成告警；未知副作用只隔离对应 Ticket，重启后从事件投影恢复隔离状态。

## 事件与迁移

- StateStore 的成功提交是业务状态唯一提交源。
- EventJournal V2 只在提交成功后，由已提交的 Ticket/Assignment/Approval/Evidence 快照确定性同步。
- 旧 ledger 保留为审计/兼容文件，不再直接成为 V2 业务事实源。
- 首次迁移生成状态与 ledger 备份、manifest、映射、不可恢复记录和投影差分。
- V2 支持 64 KiB 单行上限、64 MiB 封片、跨片 digest 链、活动尾损坏修复和 100,000 事件重放。
- 未知外部副作用不会因为重放事件而再次执行。

## 设置与原生能力

- 模型路由页的 Agent 卡默认全部收起，逐卡展开，保存失败时会展开错误卡。
- Jev 官方和第三方模式互斥；第三方模式继续使用供应商、模型、reasoning 三个下拉框。
- 设置页源码拆为 shell、locale、route model、controller、Jev 和组件模块，并继续由构建脚本合成浏览器 bundle。
- 继续使用 DSH 原生 `ask_user_question`、`todo_write`、time-context、AGENTS.md、jobs、goal、计划模式和 Git worktree；Swarm 只在这些公开 seam 上增加 Ticket、证据、租约和 Worktree 绑定。
- 可编辑专家必须先创建隔离工作树；工作树不得跨 Ticket 复用，默认保留供人工核对，不自动 remove 或删分支。

## DSH 与 pi-ai

- 推荐宿主：`0.2.1-rc.5`。
- 运行时 `pi-ai`：`1.5.0`。
- DSH 与 `dsh-llm-pi-ai` 使用精确同版本树；pi-ai 继续作为 llm adapter 的依赖由宿主解析。
- Google 订阅页的百分比是“已用比例”，99% 只表示仍有极小余量，不保证供应商接受下一次请求。若上游实际返回 HTTP 429 `RESOURCE_EXHAUSTED / Individual quota reached`，带同版本与模型区块的失败事实优先于页面百分比；自动切到备用模型是预期行为。
- pi-ai 1.5.0 的官方 `openai/gpt-6.1-sol` 目录仍声明 `contextWindow=272000`。本机 profile 使用准确的 `contextWindow=1050000`、`maxTokens=128000` 覆盖；`272000` 是长上下文计价阈值，不是模型上限。
- 本机第三方提供商插件升级到兼容 rc.5 的本地构建；订阅插件基于 `0.9.12`，保留 Claude 空文本块和 Gemini 4 Argon 兼容修补。
- 无法声明为 rc.5 兼容的插件会被 DSH 主动跳过，不能通过全局版本豁免掩盖。

## 升级与回滚

升级前备份全局 DSH、profile、profile lock、本地 bundle、状态目录和 ledger。升级后核对：

```sh
dsh --version
npm ls --prefix /usr/lib/node_modules/@deepseek-ai/dsh @deepseek-ai/dsh-llm-pi-ai @earendil-works/pi-ai --all
dsh --profile web --dump-config
```

若失败，停止 DSH，恢复升级前全局 DSH tar、profile tar 和本地 bundle，再启动旧服务。不要用 V2 未完成状态覆盖旧 StateStore。

## 边界

- Event replay 只重建业务投影，不重放外部副作用。
- 额度未知不等于零；缺失窗口不等于无限额度。
- `pi-ai` 的上游目录错误由精确 profile 覆盖处理，Swarm 不修改其他 provider 的目录。
- Release 包只包含运行代码、公开文档和必要 notices，不包含测试、PRD、审计、部署记录或私有会话证据。
