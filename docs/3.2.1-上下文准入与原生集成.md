# 3.2.1 上下文准入与原生集成

3.2.1 修复超大会话切换到较小上下文模型时出现“已达到输出 token 上限”的问题，并明确 3.2.0 的实际完成边界。

## 问题与根因

OpenAI 官方 `gpt-6.1-sol` 路由声明 `contextWindow=272000`、`maxTokens=128000`。问题会话的 DSH 回放测量约 `368003` tokens；选择该路由后，提供方接收到超过安全输入预算的历史，只完成 reasoning 并以 `length` 结束。全新小会话在同一 API、provider、模型和 `max` 推理档位下可正常回答，所以根因不是 API key、OpenAI provider 或 Swarm 主动改写请求。

3.2.0 的缺口是模型切换前没有容量准入。3.2.1 在派发前计算：

```text
安全输入 = contextWindow
         - max(本轮 maxTokens, 模型默认 maxTokens)
         - 4096 安全余量
```

当前会话超过安全输入时，该路由不会调用模型，并继续尝试主备链中上下文足够的候选。所有候选都不足时返回 `CONTEXT_RECOVERY_REQUIRED`，提示新建会话、分支或改用更大上下文模型；启用 DSH 压缩时也可先执行压缩，并明确“未调用模型”。

旧 DSH 没有 `ctx.tokenMeter`，或者第三方模型未声明 `contextWindow` 时保持原有行为。此检查不压缩会话、不删除历史，也不改变其他 provider 的模型目录。

## 原生 DSH 集成

| 能力 | Swarm 的接入 |
| --- | --- |
| `ctx.tokenMeter` | 读取当前会话回放测量，用于模型准入 |
| `ctx.llm.resolveModelInfo` | 读取候选路由的 `contextWindow` 与 `defaultMaxTokens` |
| `ask_user_question` | 保留原生问题工具；Swarm 授权恢复读取 `userQuestions` 投影 |
| `todo_write` | 保留原生单会话计划；Swarm Ticket/DAG 仍是任务与门禁真源 |
| `time-context` | 由宿主注入时间与浏览器时区，Swarm 不重复实现 |
| `agent-instructions` | 宿主加载 `AGENTS.md/CLAUDE.md`；worktree 切换 cwd 后继续由宿主生效 |
| `job_*` / `ctx.jobs` | 使用宿主作业生命周期做租约、完成通知和恢复判断 |
| `goal` | 绑定宿主 goal，停止或受阻时 disarm，不复制 goal 状态 |
| 计划模式 | 保留宿主计划审阅；Swarm 规划审核继续作为业务证据层 |
| Git worktree | 可编辑专家先创建工作树；Swarm 绑定任务与 attempt，禁止跨任务复用 |
| `session-query` | opt-in 原生能力，不强制启用，也不绕过工作区授权读取会话文件 |
| 原生 agent-team | 只读投影，不接管其调度 |

## 3.2.0 审计结论

3.2.0 已完成专家卡折叠、Jev 双来源、工作树绑定、Ticket 投影、RouteState 兼容路由、V2 事件镜像和多个独立核心模块。PRD 中的“全量 strangler 重构”尚未完整完成：

- `service.ts` 仍是主要运行时单体。
- RouteEngine、Router/Worker 和 Watchdog 尚未成为全部生产路径的唯一权威。
- EventJournal V2 尚不能独立重放并恢复全部业务状态。
- 主动 `off/observe/auto` 尚未驱动所有外部触发器。
- 旧状态兼容路径和大型前端设置模块仍在。

因此 3.2.1 是兼容性与可靠性硬化版本，不把模块存在误报为架构迁移已经完成。
