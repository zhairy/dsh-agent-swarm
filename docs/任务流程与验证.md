# 任务流程与验证（2.3）

2.2.1 在「设置 → 百工 Agent」增加工具审批设置：`approvals.mode=inherit/ask/deny`，默认继承宿主。作用域可分别选择文件修改、Shell/代码执行、外部 MCP 与内置 Jev 工具。`ask` 只向宿主申请本次许可；宿主 `never`、无应答渠道、拒绝或取消都不会执行。`deny` 可收紧权限，审批等待中改为拒绝也会在最终守卫阻止执行。该设置不控制内部规划/复评的 Jev HTTP，也不改变原生 Codex/Claude 的私有工具策略。

2.2.1 收紧可选规划审核降级：明确停用、缺少配置或临时不可用仍可按策略标注降级；认证/权限拒绝、非法响应、无效请求及取消保留未获有效审核状态。审核规则版本已更新，旧规则的批准不能用于新执行。Jev 所有入口继续不设本地限流或使用预算。

天枢调用 `swarm_task_card` 后，任务卡返回目标、验收标准、文件范围、性能要求、版本、上下文引用和 Mermaid 流程。`workflowDefinition` 是执行与绘图共用的真源，Mermaid 是派生展示，不能用一份独立图替换执行定义。流程采用有界 DAG；修复通过新轮次运行，避免流程自身无限循环。

## 启用方式

默认 `workflow.mode=advisory`，会生成流程和审核记录，兼容旧委派。希望审核未通过就阻止执行时，配置 `workflow.mode=enforced` 与 `planningReview.enabled=true`。要严格要求 Agent 和 Jev 双审，再设置 `planningReview.requireJev=true`。完整例子见 [policy.example.yaml](../config/policy.example.yaml)，应合并进现有 `swarm-core.config`。

持久化、文件消息总线、经验库默认关闭，分别用 `persistence.enabled`、`messageBus.enabled`、`experience.enabled` 开启。文件消息总线要求持久化同时开启。数学工具默认启用，扩展矩阵/多项式算子默认关闭。

## 生成后的三维审核

`swarm_review_plan` 校验当前需求、合同和流程快照。任务卡默认自动调用该流程，也可显式重审。

1. 代码检查官方 Mermaid 11.12.0 parser 与 DAG 投影一致性。
2. 新建只读御史 Agent，核查原始需求覆盖、目标与验收关系、流程依赖和分支、Mermaid 代码语义。
3. Jev 独立接收相同冻结快照，分别判断目标、流程设计和代码；Agent 和 Jev 不接收对方结论。
4. 汇总三维结果，确认审核期间需求、合同、流程或策略未改变，再存储批准。旧批准不能用来执行新版本。

结果中语法通过、投影正确、流程设计合理、目标满足需求分别有证据。概率是辅助判断，不能代替 parser、实际测试或数学证明。缺失结果、否定与不确定不会被当作通过。`requireJev=false` 时只有明确不可用才能得到标注的 `pass_with_degradation`；严格模式会阻断。自动修正轮次用尽后只暂停自动审核；任务卡仍可合法修订、收窄文件范围，并通过 `swarm_review_plan` 显式复审。修改会使旧批准失效，不能绕过执行门禁。规划控制面不消耗业务委派次数。

网页任务卡使用 DSH 原有 Markdown/KaTeX 与本地 Mermaid 模块，提供源码、缩放、适应窗口、刷新和失败诊断。服务端失败时保留文本合同与源码，不伪造完成状态。

## 执行与协作

`swarm_delegate` 可指定 `node_id`、`expected_workflow_revision` 和 `request_id`。强制模式只执行依赖满足的节点；同一请求标识不重复启动专家，输入冲突拒绝。宿主工具调用 ID 可自动作为幂等标识。

每次交付后记录目标偏离、范围越界、证据增长、收敛、协作状态和资源状态。验证证据绑定合同版本、流程版本与真实文件摘要。修改源文件、变更需求或修改门禁会使相应旧证据失效。数值性能目标需要包含环境、规模、样本数与单位的实际测量；超标不能靠描述性结论验收。

上下文分 L0/L1/L2 按需读取；先调用 `swarm_context_read` 并省略 `ref`，列出当前身份有权读取的材料和执行摘要，再按引用分页读取。`swarm_project_files` 枚举实际项目文件；路径不存在时返回真实候选，不猜测替换。私有状态/账本仍不允许通用文件工具读取。同任务修订原子替换过期材料，保存失败回滚版本和上下文；原始委派记录继续保留。专家连续会话按合同版本补充更新。简单任务使用快速流程；算法、安全、资金或并发等风险仍保留必要门禁。

开启 P2P 文件邮箱后，使用 `swarm_message_send/read/ack` 在已绑定专家之间通信。宿主决定身份与权限，模型不能自报可信发送者。消息按任务、工作区、版本、generation 和产物引用隔离；至少一次投递，接收方应按消息 ID 幂等处理。读写通过专家工具直达邮箱，无需天枢转述正文。

御史与算衡验算先在新的盲审会话冻结初审，不读取作者推理/历史经验或 P2P 消息。初审后同一版本、同一产物可委派 `review_phase=response` 做交叉回应。回应不替代初审门禁；产物改变后需重新盲审。经验先存为候选，当前源任务验收、真实独立御史和复核证据齐备后才晋升；未晋升候选不自动注入专家上下文。

持久状态保存任务、流程、身份、上下文、邮箱、预算、线程、经验和路线健康；账本仅用于脱敏审计。恢复中的运行节点标记中断/需核对，写任务不自动重放。同一真实工作区的写入与验证租约互斥；取消信号不等于子进程已停止，未知副作用状态保留阻断。权限守卫属于插件工具层，不能宣称提供了原生 shell 的操作系统隔离。

## 探索结果与持久专家控制

探微、博闻完成后，按实际代码片段/哈希和公共来源内容进行 Jev 独立评分，分别保留可信度、项目关联度、来源支撑和原始判断分布。confidence 是分布集中程度，不能当作正确率。缺来源、低相关、过期或失败标为未知/需核实；与结论相反但可靠的来源保留。评分绑定任务、需求、流程和产物版本；上下文读取重新核对代码指纹，P2P 引用显示同样的消费标识，消息摘要自身仍需核实。来源读取限制大小、时间和跳转，拒绝私网地址及敏感文件别名。

持久子对话的模型控制分别显示“实际调用”和“下一次选择”。换模型只保存后续选择；停止先发真正的祖先中断，等待实际结束和资源结算，再通过原任务/DAG/预算管线继续同一个 child。控制带版本 CAS，不能从 RPC 自报身份或资源策略。已完成任务不重复执行；未知副作用保留 `recovery-required`，确认提示不替代宿主状态和租约核对。冷父会话查看只读取官方存储，显式操作才激活真实父会话；缺 lineage、未闭合 turn 或待送达输入不能假定已停止。

## 额度耗尽与模型资源

`subscription` 表示计划/订阅额度资源，`metered_api` 表示按量 API，`judgment_api` 表示判断 API；使用具体路由的 `policy` 明确配置资源和额度域，避免只靠模型名推断账号。Qwen 标准单 key 路由默认共用 plan 域，OpenCode Go 默认按模型域隔离；Claude/Codex 的真实账号域未知时保持 unknown，可显式配置。

确认 quota/balance/pool 耗尽、认证无效或模型不可用时，在宿主长退避前切换可用备用模型。`pool "claude-opus-5-5" exhausted: every member is unavailable or failed` 加 `9060669ms` 的场景已纳入真实 AgentLoop 集成测试。所有备用终止时明确结束，不由专家外层再次启动十多次。共享域健康跨角色/线程生效；供应商明确的 `resetAt` 与插件探针 `retryAt` 分离，无 reset 的临时池/认证/目录故障也有有界恢复时间。单一半开所有者实际成功后才解除隔离，取消仅释放探针。真实 reset 未到时人工强制重试也不能越过。

升级链与基础链共同的按量末级兜底保留在基础订阅后；显式 API 主选保持原顺序。保留本次任务兼容的完整候选链，在新逻辑 step 的安全边界重新检查首选资格，同一请求不回打刚失败路线；根会话恢复尊重 `agents.rootRecoverMs`，`0` 关闭自动恢复。SDK 自动 request/header 不代表人工选模；任务验收、标记未完成或关闭升级会清除自动升级覆盖，人工选择不被模型工具的 `upgrade: true` 撤销。恢复准备记为 `route/recovery-probe`，真实成功才记为 `route/recovered`。

上下文超限单独处理：调用宿主真实压缩，只在 surface replacement 确实前进后同请求恢复一次；未缩短则暂停为 `context_recovery_required`，不能换模型重复超长历史。

DeepSeek 官方 API 与 Jev 不按订阅配额限制；API 仍可能返回余额或上游故障。Jev 在插件所有入口不设 RPS、调用量、token 或费用上限，旧 `maxRequestsPerSecond` 非零值也被忽略。单次体积、超时、有限临时故障重试仍有效，避免单请求永久悬挂。

`execution.profile=bounded` 默认委派上限 quick=6、standard=16、algorithm=20；`legacy` 保留旧不限模式。数学调用单独计数，Jev 完全排除。token/费用缺观测时记录 unknown；配置正上限但没有可信估计时拒绝启动，不能以零消费冒充预算已正确执行。完整生成模型用量采集与原生后端内部重试仍需宿主支持。

在线调整预算保留当前任务已消费记录：已有请求在原预算句柄中结算，限额变更时阻止新请求绕过在途消费，收尾后按新限额检查下一次启动。设置页修改模型链会保留显式资源/额度域 policy；类型显示来自后台同一推导，实际账号域仍需用户或适配器明确配置。

## 纯函数数学工具

`swarm_calculate` 支持 `float64`、十进制字符串 `bigint` 和分子/分母字符串 `rational`。固定算子包括四则/比较、gcd/lcm/二项式、补偿求和/均值/方差、点积/二范数与容差比较；开启扩展后增加多项式求值、矩阵乘法和 Ax-b 残差。例：

```json
{"task_id":"T-1","op":"sum","mode":"float64","args":{"values":[10000000000000000,1,-10000000000000000]}}
```

没有动态 eval、文件/网络访问、随机数或 shell。默认输入 JSON 128 KiB、单数组 4096、总元素 8192，整数输入/输出 4096 bit、中间值 8192 bit，矩阵维度 32、乘加 32768、多项式次数 1024；资源限制不能用 0 关闭。越界或非有限数返回有界诊断。结果标为 computed，数值检验不等于 proved；proved/refuted 交付必须附证明或反例正文并独立验算。
