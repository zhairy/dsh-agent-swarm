# 依赖与宿主兼容

本页说明 DSH 0.2.1 链路中哪些依赖为什么锁定，以及能否直接升级。

## 当前矩阵

| 依赖 | 声明/实际 | 升级边界 |
| --- | --- | --- |
| `@deepseek-ai/dsh` | `0.2.1-rc.5` | DSH 各内部包共享 Cordis Context、事件与 wire 类型；必须整套升级 |
| `@deepseek-ai/dsh-llm-pi-ai` | `0.2.1-rc.5` | peer 精确指向同版 DSH seams，不能与 rc.3 混装 |
| `@earendil-works/pi-ai` | `1.5.0` | `dsh-llm-pi-ai` 允许 `^1.1.0`，但安装树和锁文件决定实际版本 |
| `@earendil-works/pi-schema` | `1.5.0` | 与 pi-ai 同版本发布，避免 schema/runtime 漂移 |
| `@earendil-works/pi-telemetry` | `1.5.0` | 与 pi-ai 同版本发布，避免 replay/遥测格式漂移 |
| `openai` | `7.19.0` | pi-ai 精确锁定，暂不能单独升级 |
| `@anthropic-ai/sdk` | pi-ai 使用 `0.129.0` | Claude 子智能体链另有 `@anthropic-ai/claude-agent-sdk` 与 `0.93.0` 消费方，不能全局压平 |
| `@google/genai` | `2.21.0` | pi-ai 精确锁定，需 provider 合同回归后再升 |
| `@aws-sdk/client-bedrock-runtime` | `3.1127.0` | pi-ai 精确锁定，随 Bedrock provider 一起验证 |
| `zod` | DSH 内部多为 `4.4.3`；AI SDK 链为 `4.6.x` | 两代均满足 zod 4 的 peer 范围，暂时保留双解析 |

`dsh-llm-pi-ai@0.2.1-rc.5` 声明 pi-ai 为 `^1.1.0`，所以 1.5.0 属于允许升级。旧安装显示 1.4.0，是因为当时的安装树/锁文件已经解析到 1.4.0；全局 rc.5 重装后实际解析为 1.5.0。

## Windows 状态目录 durability

Linux/macOS 使用严格的文件与目录 `fsync`。Windows 的 Node 文件句柄不支持目录 `fsync`，通常返回 `EPERM`；3.3.2 对已经成功完成的文件 `fsync` 和同卷原子 rename 保留持久化，同时把目录项保证明确标记为 `windows-best-effort`，并保留其它权限错误。`doctor` 会显示当前平台对应的保证。

## OpenAI 模型目录误差

pi-ai 1.5.0 对直接 `openai` Responses 目录中的 GPT-6 API 模型仍写入 `contextWindow=272000`。OpenAI 当前文档给出的直接 API 规格是：

| 模型 | 上下文 | 最大输入 | 最大输出 |
| --- | ---: | ---: | ---: |
| `gpt-6-astra` | 1,050,000 | 922,000 | 128,000 |
| `gpt-6-luna` | 1,050,000 | 922,000 | 128,000 |
| `gpt-6-sol` | 1,050,000 | 922,000 | 128,000 |
| `gpt-6.1-sol` | 1,050,000 | 922,000 | 128,000 |
| `gpt-6.1-terra` | 1,050,000 | 922,000 | 128,000 |

3.3.1 只在 provider ID 精确为 `openai` 时应用这张表。`codex`、`openai-codex` 和第三方兼容网关不继承公共 API 容量；官方文档明确 `gpt-6.1-sol` 在 Codex/ChatGPT Work 中默认上下文为 500K。详细修复与回滚见 [3.3.1 OpenAI 元数据与输出上限](3.3.1-OpenAI元数据与输出上限.md)。

## 为什么锁

- DSH 内部包是同一个 monorepo 的协作协议。Context 服务、Session、LLM seam 和 Typert codec 以精确版本互相引用，半套 rc.3 + 半套 rc.5 会产生 missing service、重复 class 或 codec 不兼容。
- pi-ai 对 provider SDK 使用精确版本，因为不同 OpenAI、Anthropic、Google 或 Bedrock SDK 版本可能改变请求字段、流式事件或错误码。只把其中一个 SDK 提升到 latest，会绕过上游组合验证。
- Claude 订阅链和 pi-ai 都使用 Anthropic SDK，但不是同一层。强行 dedupe 到一个版本可能同时改变订阅插件和 Claude Agent SDK 的行为。
- Zod 4.4.3 与 4.6.x 是兼容的第四代 schema；锁的是依赖解析结果，不是一个仓库内手工混用 API 的理由。
- 第三方插件若声明精确 DSH peer/engine，应发布新兼容版本或提供明确的本地兼容构建。直接使用全局 `allow-version` 会掩盖真实断点。

## 可以怎样升级

1. 先升级整套 DSH，让所有 `@deepseek-ai/dsh-*` 同版本。
2. 用 `npm ls` 和 `pnpm why` 核验实际解析树，不只看 package.json。
3. 对 pi-ai 1.x 后续版本先检查 provider catalog、replay metadata、tool streaming 和错误分类。
4. 对 OpenAI/Anthropic/Google/Bedrock SDK 只在 pi-ai 新版本显式变更依赖后升级。
5. 对供应商插件做真实订阅额度读取和最小模型调用；不能把目录可见当调用成功。
