# 升级与回退

## 升级插件

- **插件市场（dsh-market）**：在市场里更新 `dsh-agent-swarm`。
- **预构建包**：`dsh plugin --profile <profile> add https://github.com/zhairy/dsh-agent-swarm/releases/latest/download/dsh-agent-swarm.tgz`
- **源码**：在仓库目录 `git pull && npm install`（`prepare` 会重新构建 `lib/`）。

装好后重启 DSH（systemd 托管时：`systemctl --user restart dsh-web.service`）。重启前先确认没有正在运行的百工会话：重启会中断进行中的模型请求与专家会话。


## 3.3.0

- 首次启动会把已提交 StateStore 投影幂等导入 EventJournal V2；迁移目录生成状态与 ledger 备份、manifest、不可恢复项和投影差分。旧账本仍是审计文件，不直接作为新业务事实源。
- Router 默认禁止天枢直接写入、运行命令和创建工作树。需要改动时由天枢委派可写专家；旧配置可显式设置 `router.workspaceWrites: allow`，但不建议作为长期运行配置。
- 未知外部副作用会把对应 Ticket 置于隔离态；只读核对完成后才能恢复，事件重放不会自动重复写操作。
- DSH 建议使用 `0.2.1-rc.5` 与 `pi-ai@1.5.0`。依赖锁版本原因见 [依赖与宿主兼容](依赖与宿主兼容.md)。
- 精确模型覆盖不会被 pi-ai 升级覆盖：`gpt-6.1-sol` 的 profile 值保持 `contextWindow: 1050000`、`maxTokens: 128000`，因为上游官方 provider 目录仍错误地写为 272000。

## 从 2.x 升级到 3.0

配置与持久状态格式不变，无需迁移。行为变化：

| 变化 | 影响 |
|---|---|
| 观察模式（默认）不再自动做规划审核 | 建卡不再等待独立审核；需要时天枢调用 `swarm_review_plan`。强制模式照旧自动审核 |
| 任务卡流程草稿缺少必需门禁时自动补齐 | 不再出现「workflow 缺少必需门禁 G_MATH_VERIFY」之类的报错；与门禁顺序冲突的草稿依赖被绕过，其余业务先后保留 |
| 链尾临时故障、他人半开探测、准入时暂无可用路由都在 `agents.networkWaitMs` 预算内等待 | 多个专家共用订阅路由时不再因另一位专家的失败立即报 `route_chain_exhausted`；同一会话 30 分钟最多等 3 次的限制取消，改为每个请求最多等 32 次 |
| 等待期间人工换模型以人工选择为准 | 醒来后不再改回等待前的目标 |
| 模型池/认证冷却按宿主恢复时间隔离（至多 30 分钟重探） | 重新登录或普通目录/配置更新不会使健康隔离提前到期；`llm/adapters-updated` 只清额度元数据缓存。等待冷却，或在已有「模型与恢复」面板请求按策略判定的受控重试，不能绕过供应商 `resetAt` 或他人的半开探测 |
| 不再仅凭 `AUTH` 标记认定凭据失效 | `AUTH` 报告订阅模型池耗尽仍按认证失效处理；其他情况按状态码与消息细分，401 等明确认证证据仍会触发认证隔离。「Access to model denied」只隔离该模型；令牌刷新失败若只有 `AUTH` 标记，不足以认定凭据失效 |
| 持久专家只在取消、打断（`aborted`）或回合被拦下（`refusal`）时暂停 | 模型错误后在同一会话自动续跑，不再停在「已暂停等待恢复」；续跑期间不提供会打断自动恢复的「继续」 |
| 写入租约按子会话与本委派登记的宿主后台作业状态核对 | 正常完成先等待作业收尾；取消时请求停止并等待确认。结束或释放通知只触发重查，未知副作用保留租约阻断；不保证所有场景都能自动恢复或无需重启，详见 [任务流程与验证](任务流程与验证.md#执行与协作) |
| 语言与工程规范写入全部预设，子会话与原生后端使用按语言生成的委派 persona | 预设文件 `presets/*.patch.yml` 与 `declarations.json` 已重新生成；语言要求已注入不代表可见推理一定遵循设置，观察与边界见 [使用.md](使用.md#输出语言) |

## 适配新版 DSH

3.3.0 的推荐和本机验收宿主为 `0.2.1-rc.5`，运行时解析 `@earendil-works/pi-ai@1.5.0`。DSH 0.2.2 会固定每一步模型，无法满足自动跨模型回退要求，因此继续排除 `0.2.2`。升级前备份全局 DSH、profile、lock 和本地 bundle；第三方插件必须发布/构建为 rc.5 兼容版本，不能依赖全局版本豁免。

本机另行修复了 dshmarket 1.73.1 的 npm scope 容器误报，并将市场目录和 npm 下载源切换到实测可用的官方地址。源码仓库中的 `scripts/patch-market-scope.mjs` 仅对已识别的源码形状应用补丁；这些主机维护动作不在插件启动时执行，也不会删除包目录或调整其他机器的服务配置。

公开源码树保留构建和预设生成工具，不包含维护者的测试沙箱或同步脚本。宿主假设集中在 [`src/host-contract.ts`](../src/host-contract.ts)。在独立源码目录中准备目标 DSH 版本后：

```sh
npm run build
npm run gen:presets -- --dsh /absolute/path/to/dsh/node_modules
npm run typecheck
npm run build
```

核对 `git diff presets/` 与宿主的 standard 预设，检查工具名、`ctx.subagents` 请求字段、`agent/request` 与 `agent/request-error` 事件、`system-prompt/assemble` 结构以及 `profileContext` 字段。构建通过不等于宿主集成验证通过；不要仅凭编译结果更新 `dsh.testedVersions`，也不要直接修改正在运行的安装目录。

## 回退到 2.9.3

```sh
dsh plugin --profile <profile> add https://github.com/zhairy/dsh-agent-swarm/releases/download/v2.9.3/dsh-agent-swarm.tgz
systemctl --user restart dsh-web.service
```

3.0 没有改变配置与状态格式，回退不需要清理数据。

## 卸载时保留什么

- `dsh plugin remove dsh-agent-swarm` 只移除 bundle 层。
- 账本 `~/.dsh/share/dsh-agent-swarm/ledger/` 会保留；如不需要，可手动删除。
- 原生 Codex / Claude Code bundle 与 dsh-web-search-free 是独立 bundle，需要分别卸载。

## 3.1.9

- 新增 `agents.languageExclusions`，默认 `[]`。在「专家执行」中多选服务商可取消专家过程的插件默认语言要求；显式任务语言保留，天枢最终汇总仍按默认交付语言。无数据迁移，无新增运行时依赖。
- 新的专家委派把隐式语言偏好放在每次系统提示装配中，避免连续会话保存过时的默认要求；实际路由回退后重新匹配。旧历史消息不改写。
- 订阅池的 `TRANSPORT`、`NETWORK`、`TIMEOUT` 按网络故障处理；本地冷却提示不等同于当前服务端额度。先在「设置 → 订阅」刷新额度，再根据新响应重试。
- Gemini 缺少 `thought_signature` 时切换兼容路由；不伪造签名、不自动重放已有工具副作用。
- 本机订阅插件升级到官方 0.9.11 为基础的兼容包，保留原有 Claude 空文本块与 Antigravity Argon 发现修补；该本机订阅包不随百工发行包分发。
