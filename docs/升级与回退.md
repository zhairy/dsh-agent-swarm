# 升级与回退

## 升级到 3.4.2

v3.4.2 精确支持 DSH 0.2.3-alpha.2。先在外部终端确认目标宿主和 Node.js 版本，再保存当前插件包、profile 配置及持久状态的一致快照；仅升级 Swarm 不会自动升级宿主或第三方插件。

下载官方 v3.4.2 安装包并核验 SHA256SUMS，按 [安装](安装.md) 操作。宿主桥接先做只读检查，需要应用时必须先停止目标 DSH；不能对正在运行的安装目录直接打补丁。配置与依赖核验后再按原部署方式启动。

## 状态与会话

插件延续 StateStore/EventJournal 的恢复合同。SQL 去重表随包发布；首次使用按插件支持的迁移创建。未知执行、未确认写入和未结算 lease 保持隔离，不凭旧 PID、空 jobs 或历史状态恢复写权。

自动恢复数据库、回执和可靠事件不是普通缓存。不要删除这些文件来获得新预算、绕开冷却或让旧 attempt 重新执行。独立执行服务的 state.json v2 会拒绝无法核验的旧格式；格式不符时先保留并核对。

## 回退

回退前停止使用同一状态目录的写者，保留升级后的全部状态，再恢复已知相容的旧程序、插件与必要的数据代。旧 rc.3 宿主使用保留的 v3.4.1 组合，不把 3.4.2 强行装入旧宿主。

回退插件不等于恢复 Docker 活进程。独立执行服务和 DSH 为两个生命周期；不能以停止网页服务推导所有旧执行者已退出。容器或写者停净无法证实时，继续隔离并转人工。

## 卸载

使用 DSH 的插件管理移除 Swarm。历史账本、去重记录、会话和独立执行服务不会因卸载被自动清除。若需要清理或停用，应另行核对归属和恢复需求，不对仍在使用的数据执行删除。

其他模型、Notebook、MCP 和原生后端由各自插件维护，不随 Swarm 升级、回退或卸载迁移。
