# 升级与回退

## 适配新版 DSH

DSH 仍处于预览阶段，接口可能会变。本插件把对宿主的全部假设集中在 [`src/host-contract.ts`](../src/host-contract.ts)。升级 DSH 后：

1. `npm install && npm run build`；
2. 以新版 web-app 的 `standard` 预设为底重新生成 13 个预设：`npm run gen:presets -- --dsh "$(npm root -g)/@deepseek-ai/dsh/node_modules"`，然后查看 `git diff presets/`（DSH 新增的插件行会原样保留在各角色预设中）；
3. 重启 dsh，运行 `npm run doctor -- --profile <p>`；
4. 在百工模式里做一次只读冒烟测试：建立任务卡 → 委派探微 → 查看委派结果里的模型与供应商，以及「设置 → 百工 Agent」顶部 Jev 卡片的「测试连接」。

出现异常时，优先对照 `src/host-contract.ts` 检查：

- 工具名；
- `ctx.subagents.start` 的请求字段；
- `agent/request` 与 `agent/request-error` 事件；
- `profileContext` 的字段；
- 0.2.0 起使用的 `system-prompt/assemble`、`ctx.skills.register` 与 `connection.fetch.register`。

## 从 0.1.5 升级时的旧式预设

0.1.7 起，DSH 不再读取 `~/.dsh/.agent-presets/<id>/`（`preset.yml` + `agent.cordis.yml`）。如需保留 vibe-math、rigorquant、ultramath 等旧预设，可在 0.1.7 的会话中让 DSH 使用它自带的 `editing-cordis-compositions` 技能完成迁移。技能中「Migrate a legacy preset」一节的步骤是：

1. 新建一个 bundle 目录，只需 `package.json`（声明 `dsh.bundle.patch`）和 `cordis.patch.yml` 两个文件；
2. 在补丁中插入一行 `@deepseek-ai/dsh-agent-preset` 声明：`id` 取原目录名，`name`、`description`、`order` 取自 `preset.yml`，`plugins` 原样取自 `agent.cordis.yml`；
3. 逐个核对插件名是否仍然存在。例如 0.1.7 已删除 `@deepseek-ai/dsh-workflow-worker-thread`，改用 `@deepseek-ai/dsh-workflow-ptc`；`@deepseek-ai/dsh-persona` 的配置字段是 `prefix`，不是 `text`；
4. 用 `plugin_manager` 或 `dsh plugin add` 安装，确认生效后再删除旧目录。

## 回退到 0.1.5

```powershell
dsh plugin --profile swarm remove dsh-agent-swarm
npm i -g @deepseek-ai/dsh@0.1.5-alpha.1
# 用安装第 1 步做的备份恢复 .dsh（先把当前目录改名留存）
Rename-Item "$env:USERPROFILE\.dsh" ".dsh.after-upgrade"
Copy-Item -Recurse "$env:USERPROFILE\.dsh.backup-<日期>" "$env:USERPROFILE\.dsh"
```

本插件只支持 0.1.7 的预设声明机制，无法在 0.1.5 上运行。

## 卸载时保留什么

- `dsh plugin remove` 只移除 bundle 层。
- 账本 `%USERPROFILE%\.dsh\share\dsh-agent-swarm\ledger\` 会保留；如不需要，可手动删除。
- 原生 Codex / Claude Code bundle 与 dsh-web-search-free 是独立 bundle，需要分别卸载。
