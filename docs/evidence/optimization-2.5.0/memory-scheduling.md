# 2.5.0：记忆、上下文与委派调度审核

## 实现与权限边界

- 复用当前根会话及工作区绑定的 `FeatureState.experiences` 和 `ExperienceRepository`，没有新增第二套任务库、全局跨会话知识库、向量数据库或 embedding 服务。
- `memory.enabled` 默认关闭。开启后仅召回已经独立复核晋升、尚未过期、处于检索 TTL 内的历史经验。候选、废弃经验、未来时间记录及当前任务来源不会自动注入。
- 召回算法为明确标注的 `bounded-lexical`：英文词及中文二字片段只用于相关性排序。每条返回出处、合同/流程版本、产物摘要、复核者、适用条件、排除条件、算子版本和时间戳，并标记 `applicabilityUnverified`。相似性不构成本轮算法正确、源码仍然相同或门禁通过的证据。
- 御史、算衡验算与复核不自动接收历史记忆。历史正文以 JSON 引用材料注入；宿主覆写私有 `referenceMemory`，模型参数不能自行提供可信历史。
- 适用条件、排除条件、反例与算子版本必须完整容纳在引用预算内；否则整条跳过。仅结论摘要允许明确标记截断。原始上下文、证据和对话不被替换或删除，TTL 只控制检索资格。
- 经验候选仅在同源版本/产物、相同结论、条件、验证、反例及算子版本完全一致，且原候选未过期时复用 ID；不延长原候选有效期。已复核、废弃或过期记录不会吞掉新候选，也不会因去重自动晋升。
- 上下文路径仅做字符串完全相同的去重，不把相对路径、符号链接和别名冒充相同文件。权限仍由原 `ContextStore` 每次按根、工作区、任务、版本、线程及盲审状态核对。

## 实际调用链

`service.delegate` 先捕获合同/流程/需求版本并检查已有请求 ID → 本根会话的有界 scheduler → 原任务锁内准入与版本核对 → 原规划审核、DAG 依赖和预算预约 → 工作区租约 → 当前产物快照 → 非独立审查角色的可选历史参考 → 现有模型路由/回退 → 实际专家调用 → Jev/证据整理 → 最终版本核对与持久提交 → 释放执行槽。

调度发生在任何工作区租约和任务锁等待之前。活动槽覆盖完整委派与证据提交，不能在原始模型结果刚返回时提前归还。调度器不建立新任务、自动拆任务、跳过依赖、放宽预算、改变角色工具白名单、重放工具副作用或自动提高并发数。

三种策略只重排已经提出的请求：

| 策略 | 等待队列行为 | 限制 |
| --- | --- | --- |
| `fifo`（默认） | 按进入队列的先后顺序 | 不依据任务字数、关键词降低审查强度 |
| `priority` | 显式整数优先级高者先执行，相同优先级保持 FIFO | 不抢占已运行任务；持续高优先级流可能延后低优先级请求 |
| `roundRobin` | 按角色组轮转，组内 FIFO | 每个根会话独立，不保证不同根会话之间的全局公平性 |

默认每根会话最多 8 个活动请求、128 个等待请求；设置允许的最大值分别为 32 和 512。活动数包括等待工作区租约或远程复评的委派，因此实际同时生成的模型请求可能少于活动槽数。队列满时返回固定 `SCHEDULER_FULL`，不建立任务预约。等待可由调用方取消或服务关闭终止；不额外设置专家执行时间限制。

## 性能与复杂度

设 `Q` 为等待请求数，`A` 为活动请求数，`E` 为经验数，`B` 为经验字段字节量，`K` 为输出命中数，`L` 为每条评分文本长度，`T` 为查询词数。

| 路径 | 时间 | 额外空间与容量 |
| --- | --- | --- |
| 调度选择与移除 | FIFO、优先级、轮询当前数组实现均为最坏 `O(Q)`；FIFO 选择本身为 `O(1)`，数组移除仍需移动元素 | `O(Q + A)`；队列受配置上限约束 |
| 等待取消 | `O(Q)` 查找及移除 | 不保留已取消作业或 abort 监听器 |
| 经验存储读取 | `readFields(['experiences'])` 的复制为 `O(B)` | 不再为经验读取复制整份任务、上下文及账本状态 |
| 词法筛选与排序 | `O(E × T × L + E log E)` | 最多检查 1024 条、64 个词；评分文本最多约 4129 字符 |
| 引用构造 | 至多对候选作有界预算检查，输出 `O(K)` 条 | 默认最多 3 条、4000 JSON 字符；硬上限 10 条、16000 字符，另有固定引用提示前缀 |
| 完全相同路径去重 | 平均 `O(P)`，`P` 为路径数 | `O(P)`，不解析或改写文件路径语义 |

这些改动没有测量模型生成吞吐或完整任务 Token 节省率，因此不宣称固定百分比提速或节省。调度上限是新增的真实并发控制；升级前已有的机制为委派预算和工作区租约，不存在可复用的旧 `maxActive` 设置。

## 正反论证与回归

正方实现依据：原有经验库具有复核晋升、有效期和出处，可以安全提供有界历史参考；有界调度能防止瞬间大量委派产生无界等待，显式优先级与角色轮转可改善调用顺序。

反方提出并纳入实现的约束：排队前捕获版本，排队后不得把旧请求重新解释为新合同；幂等完成结果在队列满时仍可返回；活动槽覆盖完整证据提交；不在持有租约或任务锁时等待调度；候选/过期/历史结论不能污染盲审；适用与排除条件不得因上下文压缩丢失；无真实接口不能宣称向量检索。

已执行五个定向测试文件，共 34 项通过：`scheduler`、`memory`、`experience`、`role-registry`、`scheduling-service`。其中服务级回归实际覆盖：

1. 等待期间合同改版后拒绝旧请求，不启动新模型或预约预算。
2. 等待取消和队列满均不创建委派/执行副作用。
3. 队列满时已完成请求 ID 的精确回放仍成功，未增加模型调用。
4. 原始模型完成后的证据整理继续占用活动槽；其他根会话保持独立。
