# 2.5.0 独立反方审核

审核范围为本轮新增的多图投影、语言设置、经验召回、有界调度及其与既有版本、预算、审批、租约和持续会话的关联。审核采用源码分析、与实现专家直接互驳、独立服务级回归和慢响应反例；未修改生产状态或构建源码目录的 `lib/`。

## 原方案的修订

1. 保留已有任务状态作为唯一执行权威，五种图表与进度只读派生，不建立第二套可写状态或自动纠偏派发器。
2. 完成比例指当前有效完成的委派节点，不代表工作量、独立门禁或任务验收；失败、跳过、阻塞、未知分别披露。
3. 委派记录中的 `startedAt` 是登记时间，`durationMs` 包含等待。时序图明确反映记录的登记与终结，不冒称逐模型调用或耗时比例。
4. 语言控制适用于可见交付，显式本轮要求优先于默认；不声称控制隐藏推理，也不因语言差异重新执行业务。
5. 复用会话及工作区隔离的经验库。仅已独立复核、未过期的经验提供参考；不把词法命中当作当前证明，不污染独立盲审。
6. 调度只重排已提出请求，不自动拆解、补偿或提高授权。排队发生在租约及任务锁之前；完整委派和最终证据提交占用活动槽。
7. 禁止结果缓存跳过有副作用的委派或复用旧验收。原方案中的旧并发参数、配置路径和 CLI 伪代码改为真实接口；Archify 以实际上游 schema 验证为准。

## 发现并修复的问题

| 反例 | 影响 | 修复与验证 |
| --- | --- | --- |
| `toPolicyDraft` 没有复制新增语言字段 | 已保存英文等语言在修改旧策略时静默回落简中，刷新和重置显示异常 | 补齐语言字段；独立验证四种非默认语言往返及未知配置保留 |
| 旧 persona 写死“summary 用中文写结论” | 与新语言要求冲突，尤其持续会话和原生后端 | 删除旧硬编码；三种提示风格及三类任务提示均验证语言契约 |
| 每 5 秒重启读取 effect | 慢 RPC 响应一直被丢弃并累积未完成请求 | 成功响应后才安排下一次；组件级单 transport；15 秒等待超时后停止自动刷新，迟到结果不发布 |
| RPC 重复生成完整五图 | 重复排序、构造源码与计算摘要 | 复用已经生成的任务视图与图表快照 |
| 发布文件白名单遗漏离线图表导出脚本 | 资产安装后无法使用文档中的 Archify 导出入口 | 主审将脚本加入候选包白名单，最终工件验证另行确认 |
| 关闭 FeatureStore 前未保存锁内完整状态，锁外预检还可能迟到发布 | 已实际启动的子代理在冷恢复中丢失记录，或关停后继续启动工作 | 关停入口冻结新发布，在任务锁内保存完整 owner 状态后关闭；已发送预算保留，重启标记未知且不重放；单 owner checkpoint 失败也继续清理其他 owner，并明确聚合失败 |

超时和卸载保护不代表上游传输已经取消；手动重试仍等待已有 transport 结束，不开启无限重叠请求。未因这些修复放宽任务门禁、模型健康或数学预算。

## 独立回归

`tests/unit/upgrade-250-adversarial.test.ts` 含 16 项独立测试，覆盖：

- 四种非默认语言在旧策略编辑中保留，未知配置不丢失。
- 一次性、已知任务持续会话追加和原生提示的语言一致性。
- 同请求 ID 竞争只创建一个子代理，返回同一最终记录。
- 排队期间合同改版拒绝旧请求；排队取消不创建委派或调用模型。
- 等待队列满时已完成的幂等结果仍可读取。
- 重复五图读取不修改任务版本、规划审核或验收状态。
- 10 秒慢响应仍能发布，下一次轮询等待成功后 5 秒，不叠加请求。
- 15 秒超时停止自动轮询，迟到响应不发布。
- 手动刷新、会话切换与过时排队读取共享单 transport，旧队列不再派发。
- 人为暂停持久身份绑定，使实际已启动子代理尚未完成 `delegation/started` 持久提交；此时关停仍保留记录，冷恢复标记 `recovery_required`，已经发送的委派预算保留为 `settled / usageUnknown`，不会再调用子代理。
- 人为暂停锁外额度预检后关停服务，放行迟到预检也不能发布新的子代理；重复关闭保持幂等。
- 对第一个 owner 的关停 checkpoint 注入失败，仍关闭两个 owner 的存储并返回固定外层错误；重复关闭复用同一拒绝 Promise，两个 owner 均能重新加载各自最后有效任务，没有遗留占有锁。

初轮联合定向运行：7 个文件、86 项通过，包括独立回归、五图与官方 Mermaid parser、客户端、调度、记忆、设置页及原有流水线原子性。清理无效 loader 参数后又单独重跑客户端和独立回归。后续全量运行发现关停竞态，因此追加上述两个确定性关停反例，均通过；TypeScript 类型检查再次通过。

关停修复后的独立联合运行为 `task-runtime`、`upgrade-250-adversarial`、`pipeline-atomicity`、`scheduling-service` 四个文件，**64 项通过**。过程中曾发现关停文案合并移除了原取消错误的“已取消”，已恢复明确反馈并重新运行上述四个文件通过；没有通过改弱旧取消断言来接受新实现。

全量测试继续暴露了既有真实 journal 故障注入后的关闭场景：失败的存储句柄会拒绝最终 checkpoint。实现改为逐 owner 清理并聚合错误，保留原回滚及冷恢复断言；独立双 owner 反例与真实 journal 故障文件联合 **28 项通过**。没有把 I/O 失败转为成功，或绕过存储隔离重试写入。

这些是源码及受控运行时证据，不等于真实供应商生成、生产升级或最终发布已通过。主审仍需以私有候选 SDK、浏览器、本机升级和发布工件证据分别验收。

## 保留边界

优先级策略不保证低优先级请求无饥饿；轮询公平性按单根会话内角色组定义。经验召回是有界词法匹配，不是向量检索，字符预算不冒称精确 Token 数。新增调度、图表和召回没有证明固定的端到端提速或 Token 节省百分比。
