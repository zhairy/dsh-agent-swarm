## 已证实根因

1. 四轮独立审核仍在正常工作，却被 180000ms 总截止取消。两轮正在生成 structured_output 参数，距取消仅75/79ms；四轮累计93次工具调用，未发现首次结束前的供应商额度错误。详见 [逐轮日志证据](log-findings.json)。
2. 原版设置0仍回退为180000，无法配置不限总时长。现默认0，仅取消插件的总时长截止，用户取消、宿主关闭、迟到能力撤销、版本比较及负结论缓存全部保留。非法或溢出定时值明确拒绝。
3. 四份实际审核快照都是advisory，旧恢复提示却无条件声称未批准就禁止执行。现在任务卡/状态展示真实workflowMode，恢复提示区分advisory/enforced，用户明确的先审后执行要求仍须遵守。
4. 三次实际问答确认位于成功的ask_user_question工具结果，旧需求读取仅看user消息，漏掉授权。现按真实调用配对保存问题、选项、选中答案及逐条出处；取消、伪造选项、错调用ID和无配对结构包不能作为授权。旧聚合记录如实标注，不能伪造已恢复全部压缩历史。
5. 上下文页默认8000 UTF-16单元，但工具未说明上限。10000等合法超大请求现在收窄单页，并返回实际大小/nextCursor；不丢弃后续页。越权、旧版本、摘要错误仍拒绝，旧材料不会自动改标签成为当前批准。
6. 结构不合格的已返回审核曾被通用提示当成服务故障，状态还隐藏了具体发现。现在返回最多12条、每字段600字符的只读诊断，缺定位如实标注；不参与批准，已通过规划的非阻断建议不会诱导重复审核。

## 为什么长期目标变成blocked

目标原文未改变。根日志1691/1884行是主持者主动调用update_goal(action=blocked)，宿主随后解除自动激活。规划取消、缺失授权和语义低分叠加，导致连续没有可执行进展。百工插件本身没有自动把宿主goal改成blocked；OpenViking故障也不等于规划Agent故障。

原T-2在修复后的真实复审完整运行 **249118ms**，不再被180秒误杀，确认原文已进入requestRefs。结果仍为unknown/changes_requested，Jev图语义0.71低于0.8；发现包括合同中的旧诊断、阶段验收范围和节点映射问题，另有一条缺定位的模型输出。未降低阈值、未伪造批准、未恢复业务执行。当前swarm_status已实际显示三条发现及“审核已经返回”的说明。

## 限制及合理性

| 层次 | 当前值/行为 | 工程判断 |
| --- | --- | --- |
| 天枢和普通专家总时长 | 未设置插件统一总时长上限 | 长任务可持续执行；不等于保证最终终止 |
| 独立规划总时长 | 默认0不限，正整数可显式设置 | 活跃审查不应因固定3分钟取消；用户与关闭取消仍有效 |
| 生成预算 | 本机legacy，calls/tokens/cost均0不限；规划预算独立 | 不因规划失败耗掉实施委派额度 |
| bounded配置 | 未显式calls时quick6/standard16/algorithm20 | 为选择此模式的任务设置；本机当前未启用 |
| 重试与自动修复 | 专家重试3；自动修复2；自动规划首次+2次 | 限制重复失败，不限制正确任务的总开发时长；实质修订后可显式复审 |
| 原生后端 | 每会话3次，当前manual | 与普通API专家不同；未擅自改动 |
| 角色与独立性 | 专家maxDepth1；御史只读、盲审隔离；当前版本绑定 | 防递归委派与作者自审，保留 |
| 并发 | 8活动/128排队，宿主子Agent上限8 | 资源与排队治理，不是总时长截止 |
| 网络与流空闲 | 本机网络恢复等待180s；两DeepSeek提供方空闲300s | 空闲/网络故障与整体审查时长分开；其它provider可有覆盖 |
| Jev传输 | 单请求10s及失败重试，字符保护120000 | 无插件费用预算或调用频率限额；低分不可反复抽样抹去 |
| 上下文 | 默认8000 UTF-16单元/页，代理对可多1单元 | 分页保护输出，不限制整份任务需要的长期资料 |
| 百工状态 | 当前仍为内存模式，默认16MiB | 手动重启前须交接；OpenViking语义记忆不能替代任务/批准状态 |

数学边界、复杂度、正反审查及反例见 [代码审查报告](code-review.md)。运行观测只有阶段/耗时/模型，不包含活动心跳，不能宣传成自动停滞检测器。
