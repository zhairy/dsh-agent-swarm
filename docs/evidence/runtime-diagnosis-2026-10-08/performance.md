# 2.3.0 性能与复杂度核对

测量使用 Node 24.21.0，状态样本 15 次、预热 5 次；流程/数学各 100 次。本次没有可信前后基线，不能宣称整体提速或 28% token 节省。原始数据见 [状态基准](state-benchmark.json) 与 [流程基准](workflow-benchmark.json)。

| 路径 | 时间/空间与取舍 |
| --- | --- |
| 任务材料替换 | 按 root/task 索引扫描本任务 K 个引用 O(K)，新材料校验、哈希和回滚快照还随材料字节数增加；保留同版本有效 L2 与其他任务，预留回滚容量，不复制全部全局 Map。300 次公开服务修订测试没有累积过期引用；原始委派结果保留。 |
| 探索证据采集 | 同次采集按唯一来源缓存，读取/哈希的基础成本随总字节 B 增长；各主张摘录、评分和消费校验另计，同文件多主张的摘录仍可能重复扫描。单个本地文件/外部响应默认最多 1MiB，外部来源默认总超时 5s、最多 3 次跳转；当前没有独立的来源总数、总字节或总并发硬上限，不能宣称文件数整体有界。同次 P2P pull 按 delegation 共用校验，跨次消费重新检查代码文件。 |
| 路由恢复 | 一次候选搜索最多扫描配置链长 R，重试次数另受逻辑请求策略控制。成功请求触发超过 1024 的记录清理，扫描成本 O(L)；只删除 completed 条目，未完成/失败条目可能使 Map 继续大于 1024，因此它不是硬内存上限。同请求禁止回绕；每个相关健康故障域单一半开所有者配合局部退避，避免并发复打同一恢复资源。 |
| 持久状态提交 | 当前仍复制、校验和序列化完整状态；复制/编码随状态大小 S 增长，对象键排序另有 Σ k log k 的成本，临时空间 O(S) 且存在多份副本。默认 4MiB 是可提交业务状态的序列化字节上限，不是进程 RSS 或编码前分配上限；journal 默认 64MiB 并轮转。仍保留原始任务/委派历史，长历史可能触及 4MiB 容量限制，未实现无界归档。 |
| 状态验证 | Map/Set 索引委派与任务归属，减少反复查找；总校验仍随记录、材料大小及摘要/规范化成本增加。本轮 4000 委派/1 任务中位 4.266ms，不是 O(1) 查验。 |

内存状态合成基准的 2MiB 提交中位 13.587ms、p95 20.834ms；它不含 NAS 持久 I/O、模型、网络或生产用户延迟。20 类工作流控制面中最慢 p95 为 0.228ms（algorithm）；六类数学结果全部为 computed，只是可执行验证，不是证明。

复用和原子边界：wire reasoning effort 统一在 provider-policy；故障分类/资源域与健康隔离分别由 provider-policy/route-health 管理；实际执行路由与人工控制生命周期分别由 route-state/agent-control 管理；复用相同 DAG、合同版本、租约与预算进入恢复执行。评分只存于委派记录，消费按引用绑定；L2 材料仍包含 summary/structured/evidence 的副本，并在恢复时与原记录作规范化比对。这不是所有原始结果均已改为单份引用存储。
