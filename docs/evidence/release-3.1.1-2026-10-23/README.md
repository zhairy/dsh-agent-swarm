## 根因与修复

1. 规划审核使用专用 persona，旧前端未按角色标记识别它；独立审核路径也没有登记子会话模型控制。现在补充同源标记与一次性控制登记，`provider/model/reasoningEffort` 只来自宿主实际 attempt 观察，初始候选单独标记。
2. 一次性审核可选择下一请求模型，在途调用不中断；持久专家保留取消、宿主沉寂确认和安全继续。反方复现了在途旧请求失败把新选择误记失败的 P1；最终 `getChildFallback` 显式绑定实际失败路由，并保护预检期间再次选择、取消和跨委派旧回调。一次性 `oneShotSettled` 锁阻止迟到事件重开终态。
3. 合同修订会原子替换材料 ref，长对话可能仍引用旧 UUID。仅缺失 ref 返回 `ok:false`、当前授权材料索引和恢复步骤，没有正文、旧 cursor、批准或执行凭证。跨任务、过期版本、错误 digest、线程权限和盲审错误仍拒绝。有效持久 ref 重启后仍可恢复。
4. `glob` 超过20MB来自宿主完整 stdout 保护。没有取消该限制。文件发现支持真实工作区相对子目录，8192条目、1MiB路径索引与32KiB序列化页路径预算；取消可传播，不完整结果明确说明未扫描范围未知。已知失败只追加恢复提示，保留原错误、isError 和权限语义。
5. DeepSeek Fetch API 404不证明目标网页404，与聊天模型地址独立。用户选择内置HTTP后，只把本机 profile 的 `web.config.fetchProvider` 从 `deepseek-fetch-api` 改为 `http`，保留搜索与聊天配置；已建立权限受限备份。隔离真实 `/usr/bin/dsh` 抓取 example.com 得到200，访问回环目标被 `WEB_BLOCKED_URL` 拒绝。
6. 经验召回复用已有独立复核条目，新增最多2000字符适用条件词法匹配，保留完整适用/排除条件；盲审不注入作者经验。本轮没有自动生成或发布技能/工作流。

- `match`：抽屉采用带身份/版本/取消/过期信息的共享只读投影；不是复制每条聊天组件的独立轮询。
