# 3.3.2 运行时完整性与原生集成

3.3.2 修复旧会话持久化与事件迁移中的两个阻断故障，并增加对 DSH 原生运行表面的只读适配。

## 修复

### Windows 状态目录

Node 在 Windows 上可以打开目录句柄，但对目录执行 `fsync` 会返回 `EPERM`。3.3.2 仍对写入文件本身执行严格 `fsync`，对同卷原子 rename 后目录项在 Windows 上使用显式的 `windows-best-effort` 语义：

- Linux/macOS 继续要求目录同步成功。
- Windows 只吸收 `fsync` 的已知 `EPERM`/`EINVAL`/`ENOTSUP`，其它权限错误仍失败。
- `DurableStateStore.directoryDurability` 和 `doctor` 明确报告当前保证。
- 不把 Windows 回退描述成与 Linux 相同的掉电目录项持久性。

### 超大旧账本记录

旧版 `workflow/checkpoint` 可能超过 EventJournal 的 64 KiB 单行限制。3.3.2 在迁移层将超过 32 KiB 的 legacy data 转为有界摘要：

- `legacyDataTruncated`
- 原始 JSON 字节数
- SHA-256
- 顶层键和值形状

原始 ledger 文件保持只读且不修改。V2 记录不再因审计载荷过大穿透为模型调用失败。

### Non-event JSON 尾部

EventJournal 只在解析结果是普通对象时访问字段。活动尾为 `null`、布尔、数字、字符串、数组或空对象时，按 `invalid-shape` 截断到最后一条有效事件；损坏的已封片不会改写，后续 append 仍被拒绝。

## DSH 原生集成矩阵

Swarm 只读取宿主公开 seam，不复制其权威状态：

| 原生能力 | Swarm 使用方式 |
| --- | --- |
| `tool-ask-user` | 授权恢复读取 `userQuestions` projection；用户答案仍由宿主保存 |
| `tool-todo` | 任务视图只读展示当前会话 `todos` 摘要；不替代 Ticket/DAG |
| `time-context` | 只读展示最近消息/注入时间；实际时间文本仍由宿主注入 |
| `plan-mode` | 只读展示 active/pending；规划审批和 `exit_plan_mode` 仍由宿主控制 |
| `goal` | 绑定 goal id/revision，展示 phase/activation；不改写 objective 或 round cap |
| `jobs` | 使用 job lifecycle 做租约和完成判断；状态页只显示有界计数 |
| `agent-instructions` | 由宿主加载 `AGENTS.md`/`CLAUDE.md`，worktree 切换 cwd 后继续生效 |
| Git worktree | 可编辑 Worker 使用原生 `create_worktree`；Swarm 绑定 Ticket/Assignment |

缺失 projection 或服务时显示“未挂载”，不会阻止普通任务；doctor 会列出缺失的协作 seam。

## 与原 3.2.0 PRD 的差距

已完成的生产路径包括 TicketRepository、统一 RouteEngine、Worker 边界、EventJournal V2、Projection 化任务视图、Watchdog 和有界 scheduler。尚未完成：

- 统一 Source/Trigger 适配器尚未把主动 `off/observe/auto` 接入外部事件。
- StateStore 是当前业务提交源，EventJournal 在提交后派生；不是以 journal 作为唯一恢复源的纯事件溯源。
- 独立 durable Outbox dispatcher 和完整 Source/Thread/Eval/Subscription 域尚未实现。

3.3.2 修复现有生产路径的安全问题，不把上述未实现能力标为完成。
