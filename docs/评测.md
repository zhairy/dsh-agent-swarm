# 评测

V2 设计稿 §8 规定：**只有全部角色契约与交付模块都通过评测，才能称 V2 构建完成**。沙箱集成测试（mock 模型）验证的是插件机制本身；评测验证的是真实模型、真实订阅下的效果，只能在你本机运行。

## 样本

`tests/fixtures/eval-tasks.example.json` 已包含至少 20 个待评测样例和原有 4 个必测案例，覆盖算法边界、流程改版、盲审/P2P、长退避回退与恢复。样例清单不表示真实模型已执行；使用前应配齐该题的输入仓库和标准答案。其中：

- 至少 5 题是算法或时间序列的边界案例；
- 每题最好有标准答案或历史缺陷可以对照。

| 字段 | 含义 |
|---|---|
| `id` | 唯一 ID |
| `category` | `command` / `copy` / `vision` / `verification` / `algorithm` / `timeseries` / `general` |
| `prompt` | 在天枢会话里原样发送的请求 |
| `expectedGates` | 期望出现的门禁 |
| `expectedRoles` | 期望参与的角色 ID |
| `mandatory` | 是否为必测案例（4 个） |
| `acceptance` | 人工判定通过的标准 |

## 执行

1. 按 [安装.md](安装.md) 装好，并运行 `npm run doctor` 确认没有 ✗ 项（原生后端可以缺省）；
2. 每题在新的「天枢」会话中执行，工作区用该题对应的仓库状态；
3. 记录会话 ID，对应账本为 `%USERPROFILE%\.dsh\share\dsh-agent-swarm\ledger\<会话 ID>.jsonl`。

## 指标

| 指标 | 计算方法（数据来自账本与人工复核） |
|---|---|
| 路由准确率 | 实际委派的角色 ⊇ `expectedRoles` 的题目占比 |
| 门禁覆盖 | 任务卡的门禁 ⊇ `expectedGates` 的题目占比 |
| 严重缺陷漏检率 | 已知缺陷中，御史或复核都没有发现的比例 |
| 测试通过率 | 被验收的任务中，人工复跑测试通过的比例 |
| 性能结论可复现比例 | 带 `benchmark` 证据的任务中，人工复跑后结论一致的比例 |
| 预算 | 每题的委派次数、原生后端次数、Jev 次数（`swarm_status` 的「调用」一行） |
| 误验收 | 被 `accepted` 但实际不合格的题数，必须为 0 |

## 2.2 已运行的本地基准

`npm run bench:workflow -- --out /tmp/swarm-bench.json` 测量20类任务的流程生成、验证、摘要和Mermaid投影，以及6类固定计算；输出P50/P95/P99、吞吐、RSS、Node/OS/CPU、并发与样本数。这些数据不包含模型推理延迟或产出质量。当前结果见 [workflow-benchmark.json](evidence/implementation-2026-10-07/workflow-benchmark.json)。

可用 `--usage <records.json> --baseline-usage <baseline.json>` 导入成对真实模型用量。记录每项包含 `taskId`、`provider`、`inputTokens`、`outputTokens`，可选 `costUsd`。缺token或费用记录为unknown，不填0伪装实测；Jev仍计入完整报告，但不受插件执行预算限制。按供应商分别列出生成、审查与Jev用量；同题、同模型/参数、同质量条件下才解释节省率。当前没有实测28%收益。

完整验收命令为 `npm run typecheck`、`npm test -- --coverage`、`npm run test:integration`、`npm run build` 与 `npm pack --dry-run`。浏览器组件检查与公开宿主模型错误路径的测试范围、native/prepareCall限制在 [实施证据](evidence/implementation-2026-10-07) 中逐项区分。
