# 3.3.3 人工选模、角色恢复与事件溯源

3.3.3 修复旧会话的人工模型选择被任务卡自动覆盖，以及恢复后角色、提示词和工具 scope 可能沿用旧 preset 的问题；同时完成 Source/Trigger、durable Outbox 和 journal-only state recovery 的生产接入。

## 人工模型选择

模型选择器写入的 `model/selection` 是持久用户意图。任务卡风险规则、升级链和额度观察不能撤销该选择。

- 人工选模后，`swarm_task_card` 仍记录风险与建议，但 root upgrade 显示为 `suppressedByUserSelection`。
- 真实请求发生额度、认证、协议或网络失败时，RouteEngine 仍可执行有界 fallback。
- fallback 不覆盖人工偏好；恢复条件满足后 Priority Recovery 回到人工选择的模型。
- 旧会话通过 `inspectRootPreference` 恢复的持久选择具有同样优先级。

## 旧会话角色恢复

会话重启或打开旧子会话时，以当前 `agentPreset` projection 为准，不能继续信任内存中旧的 preset role：

- system prompt、persona 和语言策略重新绑定当前角色。
- 角色变化会撤销旧工具 scope 并重新调用 Host `tools.restrict()`。
- 当前 projection 明确指向非百工 preset 时，不再回退到旧的 routeState 角色或权限。
- 活动子会话的当前角色与执行授权角色不一致时 fail closed；必须在父天枢重新审核和委派，不能复用旧 capability。
- 已完成/已取消的专家仍不能直接消费旧 execution capability。
- 天枢继续是 Router；工作区写入、命令和 worktree 创建必须交给有权限的 Worker。

## EventJournal as source of truth

3.3.3 将状态提交写成同一 EventJournal 中的分块 transaction：

1. `state/journal-begin`
2. 一个或多个 `state/journal-chunk`
3. `state/journal-commit`

只有完整且通过的 chunk group 才进入恢复链。恢复同时校验 sequence、前序 checksum、内容摘要、整份 state checksum 和 schema；未完成的 chunk group 被忽略，完整但断链或校验失败的 group 会 fail closed。StateStore 现在是可以删除的物化缓存；journal-only 模式不从本地 StateStore snapshot/log 恢复。

恢复覆盖 14 个角色相关的 task、delegation、binding、agent control、context、budget、experience、authorization、progress 和 route health。

`events.journal=true` 时，FeatureState 的 durable authority 是 EventJournal；`persistence.enabled` 只控制本地 StateStore snapshot/log 与旧兼容 sidecar。这样默认 `persistence.enabled=false` 不会造成“Outbox receipt 已持久化但 Ticket 状态重启后丢失”的半持久化状态。

EventJournal 仍是私有 `0600` 文件，不得公开上传。旧 StateStore、ledger、route-health sidecar 与 import manifest 保留为 migration/rollback 材料。

## Source / Trigger

统一入口接受任意 Source adapter 的原始事件，并转换为不可变 Trigger：

- Source 先过滤关闭状态、忽略 Thread、自身 bot message、未允许 bot 和 plugin 注入消息。
- explicit 人工请求正常进入模型。
- inferred 候选按 `proactive.mode` 决定：
  - `off`：过滤；
  - `observe`：记录 `would-accept`，不启动 Worker；
- `auto`：至少匹配一个启用规则、具有通过任务卡 schema 校验的 Mandate，且 Thread 没有已确认 Ticket 或未完成 admission claim 时接受。
- `sourceId + externalId` 是幂等键，重启不会重复处理。
- DSH `user/message` 使用 `sessionId + seq` 作为外部 ID，插件注入消息不会冒认为人工请求。
- Thread 同时记录 Source、身份和订阅；同一 Thread 的自动/external Ticket admission 只允许一个未完成 claim。
- 已订阅 Thread 的人工 follow-up 通过 `ticket-follow-up` 以不可变 L1 `source` context 绑定到活动 Ticket，不触发新的 Eval；推断型订阅更新使用 `ticket-context` fan-out。Ticket 验收或人工停止后订阅自动结束。
- `contextOnly` 订阅接收来源上下文，但不会把后续新请求误判为已经存在的 Ticket follow-up。

Source adapter 只负责协议转换；权限、Mandate、额度、风险和 Ticket 准入仍由内核检查。

## Durable Outbox

Outbox intent 与 enabling EventJournal fact 写在同一条事件中，因此业务事实和待投递任务不会只成功一半。

- `outbox/delivered` 和 `outbox/failed` 是 durable receipt。
- intent 与 receipt 均经文件 `fsync`；每个 session 的 dispatch 串行执行，避免普通唤醒和新事件竞争同一 pending effect。
- 未注册 handler 的 effect 保持 pending。
- handler 失败使用有界指数退避和最大尝试次数。
- 到期重试和宿主重启后会重新调度已注册 handler；达到上限的 effect 以 `max-attempts` 暴露失败状态。
- `RECOVERY_REQUIRED`、`STORE_CLOSED` 或 `OWNER_ACTIVE` 不会消耗到永久失败；effect 进入 blocked，等待重启或显式 dispatch 的恢复核对。
- handler 必须按 `record.id` 保证外部操作幂等。
- `ticket-intent` 以 effect ID 作为 Ticket 的持久幂等键；Ticket 提交后、Subscription 或 receipt 写入前崩溃时可安全恢复。
- EventJournal replay 不凭空执行未注册的外部写操作；只有本版本明确注册且按 effect ID 幂等的 handler 可以恢复投递。

Auto Source 接受后产生 `ticket-intent`，由已注册的安全 handler 消费；未注册时不会凭空创建 Worker 或调用外部 API。

## 配置

现有 `proactive.mode` 与 `proactive.rules` 继续使用。Source instance、Trigger 和 Outbox 不需要新的数据库或 sidecar；它们由 EventJournal 恢复。

`events.journal=false` 时关闭 Source/Trigger、Outbox 和 journal-only state path，保持旧 StateStore 行为；相关写入口返回受控不可用错误。默认开启。

## 回滚

回滚到 3.3.2 时恢复上一版 bundle 和迁移前 StateStore/profile 备份。不要把新 journal state 误作旧 StateStore 快照，也不要自动重放未完成 Outbox。
