## 已定位的架构问题

1. `AddTaskCard` 在持久化新合同之前按累计 `planningFixRounds` 抛错，控制面停止了必要的恢复操作。修订数据必须始终可达，实际执行仍要求当前版本批准。
2. `ReviewPlan` 将独立规划审查记入任务执行的 `delegate` 预算，规划失败会挤占实现任务的调用次数。拆出可审计的规划控制面账本，迁移可明确识别的旧 `plan-<uuid>` 预约，不能退款真实执行。
3. 子会话的宿主标准 `session.selectModel/cancel` 接口拒绝 subagent-owned 会话；现有客户端只观察完成消息，无法可靠显示失败/等待中的模型。使用真实子智能体生命周期和插件控制面。
4. 路由健康记录缺少 reset 时间时可永久隔离，并且 half-open 失败又清除恢复时间。是否构成此次 ChatGPT 故障须由真实错误进一步确认；实现必须避免将认证刷新或临时目录错误变成永久额度封锁。

## 实施顺序

1. 取证与诊断：错误记录去重、根因分类、能力和调度探针清单。
2. 规划恢复：允许合同修订，暂停自动审核的状态和恢复动作，独立规划预算及旧状态迁移。
3. 供应商恢复：分类和恢复语义、隔离域、手动受控重试与回归测试。
4. 子会话控制和实际模型显示：生命周期状态机、持久化、RPC、对话界面；不能绕过真实宿主 ownership。
5. 探索证据评估：实际来源/代码摘要、Jev 原始分布、独立可信度/关联度、消费时失效检查。
6. 综合真实宿主检查与交叉审查：先确定性与故障注入，再最小真实模型任务；准确说明未测边界。
7. 本机部署与 2.3.0 发布：保留配置，回下载验包，发布说明只叙述此次变化和影响。

## 约束与判断原则

- Jev 不增加本地限流或费用/调用预算；网络取消、响应校验和有界证据大小继续保留。
- Jev confidence 表示分布集中程度，不等于事实正确率。来源支持、时效、实际代码关联与独立审查不能被一个总分替代。
- 未知、缺来源、认证失败、网络失败和过期记录不能当作通过；同时不能令合同编辑和人工修复入口永久不可用。
- 无效路径应引导基于真实文件枚举重新定位，不能自动映射成另一个猜测文件；私有状态不能改为通用读取绕过授权。
- 子智能体中断请求的 ACK 不等于停止；未知副作用恢复必须先核对。换模型不自动重放写命令。
- ChatGPT Pro 额度是否真实可用，以独立订阅请求和错误事实为证；不修改订阅凭据或伪造剩余额度。
- 发布验收逐项回到本表核对，不能用单元测试绿色替代真实宿主执行与对话操作证据。
