# 角色一览

13 个中文角色。「天枢」是主持者，其余 12 个角色可以被天枢委派，也可以在新建会话时直接选用对应预设。「衡鉴」不是会话角色，而是基于 Jev 的结构化服务：天枢调用 `swarm_task_card` 时做分流（规则 + Jev），每次委派前判断专家用一次性调用还是连续会话（见 [使用.md](使用.md#专家会话与自动重试)），每位专家交付后与天枢验收时做复评（置信度评分，见下文「衡鉴复评」）。

路由写法为 `provider/model·推理强度`：`qwen-token-plan-cn` 简写为 qwen，`opencode-go` 简写为 go，`deepseek-official`（DeepSeek 官方 API）简写为 ds，`codex` 与 `claude` 是 dsh-plugin-subscriptions 提供的 ChatGPT / Claude 订阅。每个角色默认 4 层（主模型 → 备用 1 → 备用 2 → 兜底），按顺序尝试；遇到额度耗尽、模型不可用、认证失败时自动切到下一层。层数不限，可在 Web 端「设置 → 百工 Agent」里增删。完整定义见 `src/routes.ts` 与 `src/upgrade.ts`，覆盖方法见 `config/roles.example.yaml`。

- **按能力分层**：GPT-6 Astra、Claude Opus 5.5 只承担困难决策（算衡·研算、枢机、验算，以及各角色的容灾升级）；GPT-6 Sol、Qwen3.8-Max 做日常复杂判断；DeepSeek V4.1 Flash 按推理强度兼顾复杂判断（high/max）与执行（low），Claude Sonnet 5、Qwen3.8-Flash 承担大部分执行；DeepSeek V4 Pro（含 0813）评测不高于 V4.1 Flash、价格约为其 4 倍且不支持图片，默认链不再使用，仍可在设置页手动选；MiMo、MiniMax M3、Kimi K2.7 Code、Muse Spark 作为专项和异构备用。
- **推理强度按角色调**：快速检索与执行（探微、行舟）用 low；日常判断与文案（博闻、观象、妙笔、复核）用 medium；主持、方案与编码（天枢、谋定、铸剑、疾风）用 high；架构与审查（枢机、御史）用 xhigh；数学研算与验算用 max。同一角色的备用层按各模型支持的档位取最接近的一档（例如 DeepSeek V4 Pro 只有 high/max，Qwen3.8 系列没有 high、改用 xhigh），兜底层的 DeepSeek 官方 API 同理。Web 端可以按层单独改。
- **不可用自动跳过**：没有配置的 provider、账号未开通的模型（例如 qwen 未开通 kimi-k2.7-code）会被跳过并记入账本。
- **容灾升级**：天枢、谋定、枢机、算衡·验算、铸剑、御史可以配置升级模型（其余执行类角色不提供）。命中所选触发条件，或天枢在 `swarm_delegate` / `swarm_task_card` 里传 `upgrade: true` 时，先依次使用升级模型，都不可用再回到常规链。天枢自己升级后，本任务后续的主会话请求改用升级模型，任务验收或标记未完成后恢复；你在对话框里手动换模型时以你的选择为准。算衡·验算的升级用于冲突时的第三方裁决。
- **原生升级通道**：与容灾升级无关。原生 Codex（ChatGPT Plus）或原生 Claude Code（Claude Pro）客户端只在 `swarm_delegate` 传入 `backend: codex/claude`，或设置了 `nativeEscalation: auto` 且任务属于高风险时使用，需要另外安装官方 bundle；每个会话默认最多 3 次。
- **独立性**：御史自动避开本任务实现者（铸剑、疾风）所用的模型家族；算衡·验算避开研算所用的家族。做不到时仍然执行，但结果里标注 `independence: not-achieved`。

## 衡鉴复评

每位专家交付（状态为 completed）后，衡鉴把脱敏截断后的任务目标、验收标准、天枢的委派说明、交付摘要、结构化结果与证据发给 Jev，回答四个问题：

| 题目 | 类型 | 含义 |
|---|---|---|
| 证据支撑 `supported` | noul | 主要结论有证据、推导或命令结果支撑 |
| 完整性 `complete` | noul | 回应了目标与每条验收标准 |
| 可信度 `reliability` | score（四档） | 不可靠 / 存疑 / 基本可信 / 可信 |
| 角色专项 `role_check` | noul | 按角色检查：谋定的方案与约束是否一致、算衡的证明或反例是否具体、复核的判定是否与退出码一致等 |

判定：可信度归一化到 0–1，≥ 0.67 且证据支撑 ≥ 0.6 为「可信」；< 0.4 或证据支撑 < 0.35 为「存疑」；其余为「需核实」。「存疑」会写入该委派的未解决事项，并作为 `lowConfidence` 触发条件：天枢、谋定、铸剑、算衡·验算的容灾升级默认包含它，所以同一角色重做时会换升级模型。天枢调用 `swarm_accept` 申请验收时，衡鉴再复评一次验收结论（结论是否与专家证据、门禁结果一致）。

复评只是提示，不替代门禁：Jev 的置信度表示判断的集中程度，不等于正确性。复评不设调用额度（单次约 $0.00001）；只有 Jev 关闭、未配置 key 或多次重试后仍失败时，委派照常完成，结果里注明「衡鉴复评：未执行（原因）」。单次调用约 0.3–3.5 秒。

## 职责边界

| 容易混淆的角色 | 分工 |
|---|---|
| 行舟 / 疾风 / 复核 | 行舟按既定步骤执行命令、构建、迁移演练，不改写业务逻辑；疾风直接修改小范围代码；复核决定验证集合、实际运行测试、解释失败，不修改业务文件。 |
| 观象 / 铸剑 | 观象只陈述图片中可见的事实与位置；铸剑结合代码和需求决定怎么实现。 |
| 妙笔 / 谋定 | 妙笔提供表达与体验方案的候选；谋定确定功能约束。最终取舍由天枢按任务卡验收。 |
| 算衡·研算 / 算衡·验算 | 同一角色的两次独立调用。验算只拿需求和候选实现，不读研算结论，并尽量使用不同模型家族。 |
| 御史 / 复核 | 御史做独立的工程审查（安全、维护性、性能回退），靠阅读与推理；复核靠真实命令与退出码。两者不能互相替代。 |

## 权限是怎样落实的

- 被委派的子智能体：`toolFilter.allow` 只放行上表中的工具。名单在调用时与宿主实际注册的工具名求交集，所以 DSH 改名或 Windows/Linux 的 shell 差异都不会让配置失效。
- 写文件守卫：只读、验证和限范围执行这三类角色调用 `write` 或 `edit` 时，宿主行注册的全局守卫会直接拒绝。直接选用的角色预设同样生效。
- 只读类角色预设不挂 shell；只有博闻、枢机、算衡、妙笔的预设挂 web 工具。
- 限制：预设不是安全沙箱。复核和行舟有 shell，理论上仍可通过命令写文件。因此改动由 git 快照记录，只读角色执行期间一旦出现文件改动，结果中会给出告警。
