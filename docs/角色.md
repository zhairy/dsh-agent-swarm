# 角色一览

13 个中文角色。「天枢」是主持者，其余 12 个角色可以被天枢委派，也可以在新建会话时直接选用对应预设。「衡鉴」不是会话角色，而是天枢调用 `swarm_task_card` 时运行的分流服务（规则 + Jev）。

路由写法为 `provider/model`，其中 `qwen-token-plan-cn` 简写为 qwen，`opencode-go` 简写为 go，`deepseek-official` 简写为 ds。备用链按顺序尝试；遇到额度耗尽、模型不可用、认证失败时自动切到下一条。完整定义见 `src/routes.ts`，覆盖方法见 `config/roles.example.yaml`。

说明：

- **qwen 优先**：凡是 qwen-token-plan-cn 目录里有的模型（deepseek-v4-pro/flash、qwen3.8-max/flash、qwen3.7-max/plus、qwen3.6-plus、kimi-k2.6、kimi-k2.7-code、glm-5.1、glm-5.2），都先走 qwen，再走 opencode-go。单元测试会逐条检查这条规则。
- **不可用自动跳过**：你没有配置的 provider 会被跳过并记入账本。例如还没填 qwen 的 key 时，会直接从 opencode-go 开始。
- **升级通道**：原生 Codex（ChatGPT Plus）或原生 Claude Code（Claude Pro）只在两种情况下使用：`swarm_delegate` 传入 `backend: codex/claude`；或者设置了 `nativeEscalation: auto` 且任务属于高风险。每个会话默认最多 3 次。行舟、复核、观象不走原生后端。
- **独立性**：御史自动避开本任务实现者（铸剑、疾风）所用的模型家族；算衡·验算避开研算所用的家族。做不到时仍然执行，但结果里标注 `independence: not-achieved`。

## 职责边界

| 容易混淆的角色 | 分工 |
|---|---|
| 行舟 / 疾风 / 复核 | 行舟按既定步骤执行命令、构建、迁移演练，不改写业务逻辑；疾风直接修改小范围代码；复核决定验证集合、实际运行测试、解释失败，不修改业务文件。 |
| 观象 / 铸剑 | 观象只陈述图片中可见的事实与位置；铸剑结合代码和需求决定怎么实现。 |
| 妙笔 / 谋定 | 妙笔提供表达与体验方案的候选；谋定确定功能约束。最终取舍由天枢按任务卡验收。 |
| 算衡·研算 / 算衡·验算 | 同一角色的两次独立调用。验算只拿需求和候选实现，不读研算结论，并尽量使用不同模型家族。 |
| 御史 / 复核 | 御史做独立的工程审查（安全、维护性、性能回退），靠阅读与推理；复核靠真实命令与退出码。两者不能互相替代。 |

## 权限是怎样落实的

- 被委派的子智能体：`toolFilter.allow` 只放行上表中的工具。名单在调用时与宿主实际注册的工具名求交集，所以 DSH 改名或 Windows/Linux 的 shell 差异都不会让配置失效。
- 写文件守卫：只读、验证和限范围执行这三类角色调用 `write` 或 `edit` 时，宿主行注册的全局守卫会直接拒绝。直接选用的角色预设同样生效。
- 只读类角色预设不挂 shell；只有博闻、枢机、算衡、妙笔的预设挂 web 工具。
- 限制：预设不是安全沙箱。复核和行舟有 shell，理论上仍可通过命令写文件。因此改动由 git 快照记录，只读角色执行期间一旦出现文件改动，结果中会给出告警。
