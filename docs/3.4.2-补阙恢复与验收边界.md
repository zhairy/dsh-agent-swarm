# 3.4.2 补阙恢复与验收边界

版本：3.4.2。本文说明隐藏补阙的权限、预算与自动执行边界；发布不意味着能够无人值守修复所有任务。

## 入口和模型

补阙只消费真实 Host 失败回调，不能从手动角色、preset、工作流角色或 swarm_delegate 调用。模型在百工 Agent 的模型链设置中配置 routes.bu_que.chain，默认空链，不隐式使用收费模型。只选择已配置链的首项；本版没有另建 provider 回退控制器。配置在下一次模型调用时读取。

当前实现接入请求终态失败、工具错误、任务异常/超时以及委派结果验证失败。真实 Agent 引用、当前任务/版本、项目目录物理身份和取消/暂停状态由 Host 核对；错误文本本身不授予权限。修复内部工具 call ID 由私有集合跟踪，不会递归产生新修复。注册和数据库仅在插件启用后生效。

## 去重、状态和预算

每个 Host 项目/根会话/任务/节点/合同有独立 SQLite 文件，避免跨项目和同名 T-1 相互污染；同作用域内 fingerprint=sha256(canonical_json)，不混入随机 attempt。数据库不是授权来源。

0001_failure_dedup.sql 随 lib/ops/recovery/migrations 打包，首次创建采用 WAL、5000ms busy_timeout 和事务。重复事件只累计次数；claim 使用条件更新与一次性 UUID，完成、预算和回执均有 owner 围栏。last_outcome 允许普通 TEXT；结构化结果另外携带重试键和待交回报告。

单次修复墙钟 15min、工具 60、写 20 次/5MiB、并发进程 2、同动作重试 3 次、嵌套深度 0。最终验证也计入 60 次，计划预检并为验证保留额度。写字节取实际内容或可信回滚见证，不相信模型自报的字节数。

Token/成本无上限，逐调用与修复汇总均记录；最终 usage 可修正统计，不改变执行准入。usageCoverage 标记未知计量，汇总 0 不能推导为实际免费。运行资源已消费值不退款；每动作重试键持久保存，恢复后不再获得三次新额度。

失败按 1m/5m/30m/2h/6h 退避，第五次直接转人工，6h 不构成第六次自动执行许可。成功冷却 24h；冷却后出现新失败才开启新 episode。陈旧 claim 超过 15min 转人工，不根据 TTL 接管未知写者。manual_required 不会由普通失败事件自动清除。

## 实际自动执行能力

底层 runner 可在可信 Host 明确授权的能力交集内执行受限动作；每步复核 token、路径、版本和预算，symlink 的真实目标在 prepare 前和 invoke 前核验。

当前 alpha.2 适配器自动执行限于原生 read 工具的同参数重试与验证。它不把模型选择的另一个文件或“工具调用成功”单独当作原故障恢复。新写入者、其它工具、Shell 总进程/写字节配额、回滚见证或独立业务验证不足时转人工，保留最小方案，继续使用原 Worker 的正式准入流程。没有把只读角色提升为编辑者，没有修改现有 primary/linked/verification 规则。

实际文件读取在修复专属 AsyncLocalStorage 范围锚定 Linux O_PATH/NOFOLLOW 普通文件句柄，再检查 /proc/self/fd 的真实位置后委托原 FS 实现；路径在 I/O 前被换成外部 symlink 时也不能改读外部内容。原 UTF-8/字节上限保留，普通 Agent 无范围调用原样透传，销毁恢复原 property descriptor。非本地 FS、缺 /proc 或未观察到实际 FS 读取见证时不自动验收。

自动恢复不覆盖全部代码写入。超出已验证合同的动作转人工，不能由模型分数或模拟执行器放行。

## 上下文切换失败

MODEL_SWITCH_COMPACTION_FAILED 有独立分支：保留原 request model，归为 context_exceeded，不判额度耗尽、不隔离 provider，也不重复同一普通压缩路径。

2599>=2437、2710>=2437 均要求实际 framing 后摘要严格小于 2437。候选还必须通过目标容量和必要指令/回执完整性核验。缺少公开 Host 的自定义摘要准入见证时转人工；不取消摘要更短校验、不删改历史、不伪造 generation，也不自行改用户模型。

## 交回与恢复

验证成功与 pending handoff 在同一 SQLite 事务提交。使用稳定 repair UUID 交回原主 Agent，失败后只重投报告，不重跑模型或工具。Host 适配器发送后等待公开 sessions.flush 检查点，再回读 inbox/已提交消息稳定 ID；processor 只接受匹配的 persisted 收据后确认交付。交回不唤醒暂停/空闲目标。重新绑定可信作用域时可重投未完成回执；没有确认绑定时保留待交付。

启用补阙后启动时扫描已有 scope 数据库，并以 unref 定时器每 15 秒检查陈旧 claim。即使重启后没有新失败回调，也只将超时旧 claim 转人工，不重新领取、不恢复 lease、不启动模型。维护错误保留门禁并输出上下文，不作为主 Harness 重新启停的理由。

并发 duplicate 只记去重，不封存真实 owner。回调结束后关闭空闲 SQLite 连接并释放内存关联；插件卸载取消新修复并等待回调结算。未知副作用先只读核对，无法证实时转人工，不能自动重放未知写入。

## 能力与限制

| 范围 | 验证与支持边界 |
| --- | --- |
| SQLite 去重 | 独立连接并发 claim、冷却、退避、状态机与重启回执测试 |
| Host 回调 | 原生失败回调、任务身份、取消/暂停、重复事件与递归拒绝 |
| 文件边界 | 受限文件句柄、路径替换和 symlink 回归；不等于通用恶意代码沙箱 |
| alpha.2 | 冻结前路由、工具边界、目标来源、初审及受控工作树合同 |
| 自动修复 | 仅支持已有可信执行见证的合同；未知写入、Shell、任意补丁不自动重放 |
| 摘要失败 | 必须更短且保持完整性；没有可信摘要见证时转人工 |

第三方插件兼容包、宿主 SDK、本机配置及运行记录不包含在本发行安装包中。microVM 和 Notebook 旧内核整体托管不在本版完成范围。

## 回退

按 feature 分支阶段提交 git revert；不覆盖用户已有改动。运行时关闭新调度前先结算在途动作；数据库和回执保留，不能删库重置去重。未知状态人工核对，不能凭历史记录恢复写权。
