# 3.1.2任务进度与后续路线

## 本版变化

会话的“对话 / 轨迹 / Notebook”后新增原生“任务进度”视图，集中查看执行前编排、工作流、委派架构、委派记录时序、合同与证据流、生命周期快照。Notebook未安装不影响本入口；DSH rc.3会按宽度将视图折叠进“更多”，不会强制固定Tab或改宿主DOM。

六视角按需绘制；任务、进度、版本和图表来自同一权威快照。失败保留最近正确值并标明过期；刷新、连接重建、任务切换和隐藏均有独立的取消与身份校验。取消展示读取不取消长期任务，不合作传输未结算时不反复补开请求。普通会话与受限子会话显示空态，不自动读取父任务。

节点完成比例不表示工时、正确率或整项任务验收。没有编排记录时显示“未记录”；时序含排队，生命周期只有快照时不伪造迁移历史。

启用既有经验功能后，天枢可通过`swarm_experience`的`record_tool_candidate`操作登记工具/技能来源、版本、权限需求、拟测试和回滚引用。这些只作为不可执行候选保存：`evaluation=unavailable`、`executionEnabled=false`。引用不是读取或执行权限，文本经验的晋升通道不能激活工具，候选不会进入已复核经验召回。不因此自动开启经验或持久化设置。

## 吸收Ruflo的设计

研究依据为[Ruflo固定提交](https://github.com/ruvnet/ruflo/tree/fe99f748c577158ec3e517c7b421670a4601f54f)。吸收独立任务工作区、读取与导航分离、单飞/stale投影、有来源的候选，以及回放后再提升的治理思路。实现保持独立，不复制其代码，不引入Ruflo、AgentDB或第二执行器。

Ruflo的默认超时、固定重试、任务complete、静态模型价格表不能直接替代百工长期任务、证据门禁、真实模型目录和订阅额度；项目宣称的性能数字不等于本插件实测结果。

## 后续迭代

| 版本 | 范围与边界 |
| --- | --- |
| 3.1.3 | 服务端验收凭证、真实用户问答等待、稳定谱系的全历史结构反空转、有限DAG恢复；权威提交后轻量失效通知，不建第二事实源 |
| 3.1.4 | 固定轨迹回放、语义/收益校准、候选治理、显式Canary和可恢复回滚；只调可选咨询边，不剪强制安全依赖 |

相邻语义变化小不证明任务正确或完成；等待不能被误报为空转，停滞不能当作验收。未回复、超时或默认选项不构成用户授权。3.1.2没有宣称完整授权状态机或全历史数学守卫已实施。

## 兼容与安装

保留DSH `>=0.2.0-rc.2 <0.3.0`范围，目标宿主为`0.2.1-rc.3`；旧宿主缺公开slot时保留inline图表。v1状态可读；新增候选字段可选、不可执行。升级前核对其它插件的精确宿主版本约束，使用官方同版本包或经过验证的本地兼容副本，不用全局兼容豁免掩盖拒载。

本地包优先使用`scripts/install-profile.mjs`以摘要目录和`link:`安装，保留profile其它插件与设置。升级内存态任务必须先做最新受限交接，不把历史聊天当作任务恢复，也不自动重放旧委派。
