# v3.2.0 代码审计记录

本文件是本地研发记录，不进入发布附件。

## 第一轮：功能、安全与兼容

| 等级 | 发现 | 处理 |
| --- | --- | --- |
| 高 | 第三方 Jev 健康检查曾把缺失 `resolveModelInfo` 当成模型有效 | 现在缺少宿主模型目录能力时返回 `model-catalog-unavailable`，恢复后仍要求 DSH 解析所选 provider/model |
| 中 | 第三方模型流式文本没有输出上限 | 复用 `maxRequestChars` 作为有界响应上限，超出返回 `response-too-large` |
| 中 | 空白 provider/model 会被运行时误当成有效字符串 | 运行时统一 trim 并拒绝空值，设置页同步显示未配置 |
| 中 | worktree 恢复账本未防止同一专家被多条记录覆盖 | hydrate 现在跳过重复 agent 绑定；路径必须位于 repository root 且不能等于 root |
| 低 | Jev 卡片仍显示“API Key”标题，第三方模式语义不清 | 改为“Jev 判断模型”，说明官方与第三方来源 |

官方和第三方路径按 `config.source` 互斥。第三方路径不调用 `getApiKey`、不发送 TypeSafe HTTP；官方路径不调用 DSH `llm.stream()`。相关断言位于 `tests/unit/jev-hub.test.ts`。

## 第二轮：失效模式、竞态与用户入口

| 等级 | 发现 | 处理 |
| --- | --- | --- |
| 高 | 切换第三方 supplier 时旧 model/effort 仍可能留在草稿 | 换 supplier 清空旧模型和推理档位；换模型清空旧推理档位；显式完整 patch 仍可原子设置 |
| 中 | 外部取消发生在模型流结束后仍可能接受答案 | 流结束后再次检查外部 signal 和 timeout signal；新增已取消 signal 回归 |
| 中 | DSH finish error 的统一 503 会丢失供应商 401/402/429 状态 | 从 `{kind:'error', failure:{status}}` 和抛出错误中保留 400–599 状态，供统一失败分类使用 |
| 中 | 前端读取 Jev 草稿会丢弃 `thirdParty` 的未来扩展字段 | 读取和换 supplier 时保留未知字段 |
| 中 | 可编辑专家 prompt 曾把 worktree 描述成仅特定任务需要，但守卫是写前必选 | 统一为“任何文件修改或命令前先创建”，降低无效调用 |
