# v3.2.1 代码审计与本机验收记录

## 范围

本记录不进入发布包，只保留源码仓库审计证据。发布候选为 `3.2.1`，功能范围是 DSH 原生 token-meter 上下文准入、显式模型选择、自动回退、原生插件兼容和 V2 事件诊断修复。

## 第一轮正向审计

结论：上下文准入已覆盖主路径，可以把超窗请求阻止在 provider dispatch 之前。

- `src/context-admission.ts` 的安全输入预算为 `contextWindow - max(请求 maxTokens, 模型 defaultMaxTokens) - 4096`。
- `src/service.ts` 使用真实 `ctx.tokenMeter.measure(session)` 与 `ctx.llm.resolveModelInfo()`，未知服务或容量 fail-open。
- `src/route-state.ts` 同时检查当前显式模型和声明备用链；全链不足时抛 `CONTEXT_RECOVERY_REQUIRED`，不调用模型。
- `src/index.ts` 对 `ctx.tokenMeter` 使用可选依赖，不提高旧 DSH 的硬依赖。
- `src/event-journal.ts` 保留已命名的纯 token 数值诊断字段，同时继续脱敏 `apiKey` 等密钥字段。

## 第二轮反向审计

发现的边界与修正：

1. 显式选择模型不在角色备用链时，原候选构建会直接进入备用链，未检查所选模型。已把当前显式路由仅加入本次准入候选；安全则尊重选择，超窗才回退。
2. 备用模型即使有 `500000` 窗口，在请求输出 `128000` 加安全余量后安全输入只有约 `367904`，因此接近上限的会话仍应拒绝。测试使用真实 `1000000` 窗口作为安全备用。
3. 原 V2 脱敏正则把 `measuredTokens`、`safeInputTokens` 等字段视为凭据。已增加精确 numeric metric 白名单，密钥字段规则不变。
4. 服务层测试覆盖 token meter、模型元数据、路由自动回退和测量失败 fail-open，避免只验证纯函数。
5. 原生 Todo 需避免形成第二事实源；天枢协议明确 Todo 只做会话可见计划，Ticket/DAG、证据和门禁仍是业务真源。

未发现：

- 凭据或会话正文进入错误文本、日志或发布包。
- 对其他 DSH provider 的无条件阻断。
- 未知 token-meter/context 元数据导致旧宿主不可用。
- 阻塞调用超时被当作授权或成功。
