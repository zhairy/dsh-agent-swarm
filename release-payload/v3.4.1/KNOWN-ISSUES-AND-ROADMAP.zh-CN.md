# v3.4.1 已知边界与迭代计划

本轮通过的是指定 Linux/DSH rc.3 精确组合及列举行为，没有声称所有插件业务、所有模型或全部平台绝对无缺陷。

| 范围 | 当前边界 | 影响与处理 |
| --- | --- | --- |
| 写入环境 | Linux 本机、API Worker、匹配桥接和完整物理边界 | 其它backend/未知版本不自动放行 |
| 恢复 | Notebook仅恢复cell/源码/输出和真实producer来源；默认16MiB/4096cells | 不恢复活变量/内核、不重放旧cell；dirty使旧来源失效 |
| 路由 | 有界进程内trace | 重启清空；省略数是进程总量，不是单任务精确丢失数 |
| Git保存 | 精确存在的普通文件 | 不支持递归目录、删除和任意Git；部分失败保留现场且不自动重发 |
| 复核输出 | 指定var/tmp和本次新report目录 | symlink、多链接文件、异常节点或扫描超限拒绝；不替用户自动清理 |
| 第三方/供应商 | 263个启用行冷启动active，另有指定业务抽样 | 不把active/界面额度当成每个外部服务、账号或业务均可用 |
| 评价工具 | Jev是辅助证据 | 原review、不确定和一次独立复审工具拒绝均保留，不作为无缺陷证明 |

后续迭代顺序：

1. **3.4.2优先**：用户实际任务反馈、更多项目规则与受控Git场景、兼容矩阵组合及可复现下载/升级回滚检查。每个问题先红测、修复、精确包正反例，不绕过旧门禁。
2. **后续3.4.x**：Notebook数据版本与显式跨任务导入、路由trace的受控持久导出和对比；继续测量角色/工具上下文成本。一次本机纯文本探针的输入约61K token，只是该环境的单样本，不外推性能基准。
3. **独立设计后再实施**：多语言kernel registry/预热池、依赖快照、凭据代理、网络策略、容器/gVisor/microVM及资源总配额；这些不在本版宣称完成。

业务项目原阶段、未提交源码和原自动续轮状态不因插件发布而视为完成；继续任务仍需当前合同、合法主树绑定与独立验收。不通过chmod、取消守卫、删锁或手改私有账本处理拒绝。
